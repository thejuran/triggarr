# Phase 56 — UI Design Contract

> Visual and interaction contract for the First-Run Setup and Login pages. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Python/FastAPI + Jinja2 + Tailwind CSS v4) |
| Preset | not applicable |
| Component library | none (vanilla HTML + htmx) |
| Icon library | none (no icons in auth pages) |
| Font | Geist Mono (self-hosted woff2, weights 400 + 500) |

**Note:** AIDesigner MCP generates the HTML artifacts for login, setup, and setup-success pages. The AIDesigner output is the hard visual spec -- implementation matches pixel-exact. This UI-SPEC defines the design contract boundaries that AIDesigner output must satisfy and that the executor validates against.

## Page Inventory

### Page 1: Setup Page (`/setup`)

**Layout:** Centered card on `triggarr-bg` full-viewport background. No nav bar. Card max-width 420px, rounded-lg, border `triggarr-border`, bg `triggarr-card`, padding 24px.

**Template:** `setup.html` extends `base-auth.html`

**Elements:**
1. **Brand header:** "Triggarr" wordmark in `triggarr-green`, 20px, weight 500, centered
2. **Page heading:** "Welcome to Triggarr" -- 20px, weight 500, `triggarr-text`, centered
3. **Subheading:** "Create your account to get started" -- 14px, weight 400, `triggarr-muted`, centered
4. **Username field:** Label "Username", input pre-filled with "admin", full-width
5. **Password field:** Label "Password", type=password, full-width
6. **Confirm password field:** Label "Confirm Password", type=password, full-width
7. **CTA button:** "Create Account" -- full-width, bg `triggarr-green`, hover bg `triggarr-green-dark`, text white, 14px weight 500, rounded, py 8px
8. **Validation errors:** Inline red text (`#ef4444`) below the relevant field, 14px

**Input styling:** bg `triggarr-bg`, border `triggarr-border`, rounded, px 12px, py 8px, text 14px `triggarr-text`, placeholder `triggarr-muted`. Focus: ring 2px `triggarr-green`, outline-offset 2px.

**States:**
- Default: Form with empty password fields, username pre-filled "admin"
- Validation error (password mismatch): Red text "Passwords do not match" below confirm field
- Validation error (empty password): Red text "Password is required" below password field
- Submission: Button disabled during POST, text changes to "Creating..."

### Page 2: Setup Success (same `/setup` route, post-completion state)

**Layout:** Same centered card as setup page. Replaces the form content after successful credential creation.

**Elements:**
1. **Brand header:** Same "Triggarr" wordmark
2. **Success heading:** "Account Created" -- 20px, weight 500, `triggarr-text`, centered
3. **Instruction text:** "Save your API key -- you will not be able to see it again." -- 14px, `triggarr-muted`, centered
4. **API key display:** Monospace (Geist Mono inherits), full 32-char hex, bg `triggarr-bg`, border `triggarr-border`, rounded, px 12px, py 8px, `triggarr-text`, 14px, user-select all
5. **Copy button:** "Copy" -- inline next to or below API key, bg `triggarr-card-elevated`, border `triggarr-border`, rounded, px 12px, py 4px, 14px. After click: text changes to "Copied!" for 2 seconds, then reverts
6. **Continue button:** "Continue to Dashboard" -- full-width, bg `triggarr-green`, hover `triggarr-green-dark`, text white, 14px weight 500, rounded, py 8px

**Interaction:**
- Copy button uses `navigator.clipboard.writeText()` with visual feedback (D-02)
- Falls back to selecting the text if clipboard API is unavailable
- User is auto-logged in (session cookie already set) but remains on this view to copy key first
- "Continue to Dashboard" navigates to `/`

### Page 3: Login Page (`/login`)

**Layout:** Same centered card as setup page. No nav bar. Card max-width 420px.

**Template:** `login.html` extends `base-auth.html`

**Elements:**
1. **Brand header:** "Triggarr" wordmark in `triggarr-green`, 20px, weight 500, centered
2. **Page heading:** "Sign In" -- 20px, weight 500, `triggarr-text`, centered
3. **Error message area:** Below heading, above form. Red text (`#ef4444`), 14px. Hidden when no error.
4. **Username field:** Label "Username", full-width, pre-filled on error re-render (D-04)
5. **Password field:** Label "Password", type=password, full-width, always cleared on re-render
6. **CTA button:** "Sign In" -- full-width, bg `triggarr-green`, hover `triggarr-green-dark`, text white, 14px weight 500, rounded, py 8px

**States:**
- Default: Empty form (or with `?next=` param stored in hidden input)
- Error: "Invalid username or password" in red below heading. Username pre-filled. Password cleared.
- Submission: Button disabled during POST, text changes to "Signing in..."
- Already authenticated: Redirect to `/` (D-06), user never sees form

### Shared Template: `base-auth.html`

**Structure:**
```
<!DOCTYPE html>
<html lang="en">
<head>
  <!-- Same <head> as base.html: charset, viewport, favicon, output.css -->
  <!-- NO htmx script (not needed for auth pages unless copy button uses it) -->
</head>
<body class="bg-triggarr-bg text-triggarr-text min-h-screen flex items-center justify-center">
  {% block content %}{% endblock %}
</body>
</html>
```

**Key difference from `base.html`:** No nav bar, no sidebar, no max-w-7xl container. Body uses flexbox centering. Minimal -- just the card.

### Nav Bar Modification (in `base.html`)

**Change:** Add conditional logout form to the right side of the nav bar.

**Element:** A small `<form method="post" action="/logout">` with a submit button styled as a nav link.

**Styling:** Same as existing nav links -- `text-triggarr-muted hover:text-white text-sm`. No special button styling (looks like a link).

**Condition:** `{% if auth_active %}` -- only visible when `auth_method` is "Forms" or "Basic" (D-11).

**Placement:** After the Settings link, separated by a `|` divider or gap-6 spacing (D-12 -- AIDesigner determines final placement).

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Setup form submit | POST to `/setup`, validates server-side, re-renders with errors or shows success view |
| Login form submit | POST to `/login`, validates server-side, sets session cookie on success, redirects to `?next=` or `/` |
| Copy API key | `navigator.clipboard.writeText()`, button text toggles "Copy" -> "Copied!" for 2s (D-02) |
| Clipboard fallback | Select the API key text programmatically if clipboard API unavailable |
| Logout | POST form to `/logout`, clears `triggarr_session` cookie, redirects to `/login` (D-09, D-10) |
| Already-authed visits `/login` | Redirect 302 to `/` (D-06) |
| Visits `/setup` after config exists | Return 404 (SETUP-04) |
| `?next=` redirect | Login redirect preserves original URL; validated to reject open redirects (relative paths only) |
| Focus management | Auto-focus first empty field on page load (username on setup/login, password if username pre-filled) |

## Accessibility

| Requirement | Implementation |
|-------------|---------------|
| Focus ring | 2px solid `triggarr-green`, offset 2px, radius 6px (existing `:focus-visible` rule) |
| Reduced motion | Existing `prefers-reduced-motion` rule suppresses transitions |
| Form labels | Every input has an associated `<label>` element with matching `for`/`id` |
| Error association | Error messages use `aria-live="polite"` for screen reader announcement |
| Password fields | `type="password"` with `autocomplete="new-password"` (setup) or `autocomplete="current-password"` (login) |
| Page title | "Setup - Triggarr" and "Login - Triggarr" via `{% block title %}` |
| Language | `<html lang="en">` in `base-auth.html` |
