<feature>
  <name>AuthMiddleware deny-all dispatch with D-10 check order</name>
  <files>triggarr/web/middleware.py, tests/test_auth_middleware.py</files>
  <behavior>
    AuthMiddleware is a BaseHTTPMiddleware subclass that gates every non-exempt route.

    EXEMPT_PREFIXES = ("/health", "/static", "/login", "/setup")
    Any path starting with an exempt prefix passes through without auth checks.

    For non-exempt paths, check order per D-10:
    1. needs_setup true + browser -> 302 redirect to /setup
    2. needs_setup true + API -> 401 JSON {"detail": "Setup required", "setup_url": "/setup"}
    3. is_disabled true -> pass through
    4. method == "External" -> pass through
    5. valid session cookie (triggarr_session) -> pass through
    6. valid X-Api-Key header (timing-safe via secrets.compare_digest) -> pass through
    7. method == "Basic" + valid Authorization: Basic header -> pass through + set session cookie on response
    8. method == "Basic" + invalid/missing Authorization -> 401 with WWW-Authenticate: Basic realm="Triggarr"
    9. fallback browser (Accept: text/html) -> 302 redirect to /login
    10. fallback API -> 401 JSON {"detail": "Authentication required"}

    Browser detection: "text/html" in Accept header.
    Cookie name: "triggarr_session"
    API key header: "X-Api-Key" (case-insensitive via Starlette)
    Cookie attributes when set (Basic auth flow): httponly=True, samesite="lax"

    Test cases (input -> expected output):
    - GET / with no auth, Accept: text/html -> 302 Location: /login (MID-01, MID-04)
    - GET / with no auth, Accept: application/json -> 401 {"detail": "Authentication required"} (MID-04)
    - GET / with valid X-Api-Key -> 200 (MID-02)
    - GET / with invalid X-Api-Key -> 302 or 401 (not 200)
    - GET /health -> 200 (no auth needed) (exempt path)
    - GET /static/css/output.css -> passes through (exempt path)
    - GET /login -> passes through (exempt path)
    - GET /setup -> passes through (exempt path)
    - GET / with method=Basic, no Authorization -> 401 + WWW-Authenticate header (LOGIN-03)
    - GET / with method=Basic, valid Authorization -> 200 + Set-Cookie: triggarr_session (LOGIN-03)
    - GET / with method=Basic, invalid Authorization -> 401 + WWW-Authenticate header (LOGIN-03)
    - GET / with method=External -> 200 (pass through) (LOGIN-04)
    - GET / with method=Disabled -> 200 (pass through)
    - GET / with needs_setup=true, browser -> 302 /setup
    - GET / with needs_setup=true, API -> 401 {"detail": "Setup required", "setup_url": "/setup"}
    - GET / with valid triggarr_session cookie -> 200 (regardless of method)
    - GET / with malformed Basic auth header -> 401 (not 500)
  </behavior>

    2. Define EXEMPT_PREFIXES = ("/health", "/static", "/login", "/setup") as module-level tuple

    3. Create AuthMiddleware(BaseHTTPMiddleware) class with:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> AuthMiddleware | Untrusted HTTP requests from browsers and API clients |
| AuthMiddleware -> auth.py | Middleware passes user-supplied values (cookie, password, API key) to auth helpers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-01 | Information Disclosure | AuthMiddleware API key check | mitigate | Use `secrets.compare_digest()` for timing-safe API key comparison -- prevents timing side-channel |
| T-55-02 | Spoofing | AuthMiddleware session cookie | mitigate | Cookie set with `httponly=True, samesite="lax"` -- prevents XSS theft and CSRF |
| T-55-03 | Information Disclosure | AuthMiddleware Basic auth | accept | Basic auth sends credentials in base64 (not encrypted) -- HTTPS recommended but not enforced in homelab Docker context |
| T-55-04 | Tampering | AuthMiddleware Basic auth | mitigate | Wrap base64 decode in try/except (ValueError, UnicodeDecodeError) -- malformed headers return 401, not 500 |
| T-55-05 | Elevation of Privilege | AuthMiddleware exempt paths | accept | Prefix matching could match unintended paths like /healthcheck -- acceptable because no such routes exist; documented in EXEMPT_PREFIXES comment |
| T-55-06 | Tampering | Authenticated endpoints | mitigate | Existing OriginCheckMiddleware handles CSRF for POST/PUT/PATCH/DELETE -- AuthMiddleware runs before it (registered last) |
</threat_model>
