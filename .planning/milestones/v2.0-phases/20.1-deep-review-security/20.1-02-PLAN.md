**DRSEC-02 -- XSS urlencode fix in history_results.html:**

Apply `| urlencode` filter to ALL dynamic values interpolated into hx-get URL query strings. Jinja2 auto-escaping handles HTML contexts but does NOT URL-encode within attribute values, so a crafted `search_text` could inject additional URL parameters.

Find and replace every `{{ search_text }}` within hx-get attributes. There are 4 occurrences:

1. Line 19: `&search={{ search_text }}` -> `&search={{ search_text | urlencode }}`
2. Line 42: `&search={{ search_text }}` -> `&search={{ search_text | urlencode }}`
3. Line 65: `&search={{ search_text }}` -> `&search={{ search_text | urlencode }}`
4. Line 129 (base_qs construction): `~ "&search=" ~ search_text` -> `~ "&search=" ~ (search_text | urlencode)`

Also apply urlencode to the other dynamic values in hx-get URLs that come from filter lists, since they are also user-controlled:
- `{{ new_apps }}` -> `{{ new_apps | urlencode }}` (lines 19, 42, 65)
- `{{ new_queues }}` -> `{{ new_queues | urlencode }}` (lines 42)
- `{{ new_outcomes }}` -> `{{ new_outcomes | urlencode }}` (lines 65)
- `{{ active_apps | join(',') }}` -> `{{ active_apps | join(',') | urlencode }}` where used in hx-get URLs
- `{{ active_queues | join(',') }}` -> `{{ active_queues | join(',') | urlencode }}` where used in hx-get URLs
- `{{ active_outcomes | join(',') }}` -> `{{ active_outcomes | join(',') | urlencode }}` where used in hx-get URLs

NOTE: The filter pill values (Radarr, Sonarr, missing, cutoff, searched, failed) are hardcoded safe strings joined from lists, so urlencode on the joined result is defense-in-depth. The critical fix is `search_text` which is user-supplied. Apply urlencode to ALL dynamic values in hx-get URL attributes for consistency and defense-in-depth.

For line 129 (base_qs macro), update the concatenation to urlencode each dynamic piece:
```jinja2
{% set base_qs = "app=" ~ (active_apps | join(',') | urlencode) ~ "&queue=" ~ (active_queues | join(',') | urlencode) ~ "&outcome=" ~ (active_outcomes | join(',') | urlencode) ~ "&search=" ~ (search_text | urlencode) %}
```

**DRSEC-03 -- Rate limiter check-then-act race in routes.py:**

In the `search_now` function, restructure the rate limit logic so the timestamp is written inside the search_lock. Currently:

```python
# Check rate limit BEFORE lock (fast-fail)
now = time.monotonic()
last = request.app.state.last_search_time.get(app_name, 0.0)
if now - last < SEARCH_RATE_LIMIT_SECONDS:
    ...return 429
request.app.state.last_search_time[app_name] = now  # BUG: write before lock

async with request.app.state.search_lock:
    ...run cycle
```

Change to:

```python
# Optimistic rate limit check BEFORE lock (fast-fail for obvious cases)
now = time.monotonic()
last = request.app.state.last_search_time.get(app_name, 0.0)
if now - last < SEARCH_RATE_LIMIT_SECONDS:
    logger.info("{name}: Manual search rate-limited", name=app_name.title())
    return HTMLResponse("Rate limited — try again shortly", status_code=429)

async with request.app.state.search_lock:
    # Re-check inside lock to prevent concurrent bypass (DRSEC-03)
    now = time.monotonic()
    last = request.app.state.last_search_time.get(app_name, 0.0)
    if now - last < SEARCH_RATE_LIMIT_SECONDS:
        logger.info("{name}: Manual search rate-limited (after lock)", name=app_name.title())
        return HTMLResponse("Rate limited — try again shortly", status_code=429)
    request.app.state.last_search_time[app_name] = now

    try:
        request.app.state.fetcharr_state = await cycle_fn(
            ...existing code
        )
        ...existing save_state and logging
    except Exception as exc:
        ...existing error handling
```

Key change: Remove `request.app.state.last_search_time[app_name] = now` from before the lock, and place it inside the lock after the re-check. This ensures two concurrent requests cannot both pass the rate limit check.

**DRSEC-07 -- Sanitize exception details in engine.py:**

The current code stores `str(exc)[:200]` in the detail field of search history entries. This can leak internal paths, URLs with query strings, or other sensitive info that bypasses the loguru redacting sink (since it goes to SQLite, not logs).

Add a helper function at the top of engine.py (after imports):

```python
def _sanitize_exc(exc: Exception) -> str:
    """Return a safe, type-based summary of an exception for storage.

    Avoids storing raw str(exc) which may contain internal paths, URLs,
    or API keys that bypass the loguru redacting sink.
    """
    if isinstance(exc, httpx.HTTPStatusError):
        return f"HTTP {exc.response.status_code}"
    if isinstance(exc, httpx.TimeoutException):
        return "request timeout"
    if isinstance(exc, httpx.HTTPError):
        return f"HTTP error: {type(exc).__name__}"
    if isinstance(exc, pydantic.ValidationError):
        return f"validation error ({exc.error_count()} issues)"
    return type(exc).__name__
```

Replace all 4 occurrences of `detail=str(exc)[:200]` in engine.py with `detail=_sanitize_exc(exc)`:
- Line ~246 (Radarr missing queue exception)
- Line ~280 (Radarr cutoff queue exception)
- Line ~397 (Sonarr missing queue exception)
- Line ~436 (Sonarr cutoff queue exception)
