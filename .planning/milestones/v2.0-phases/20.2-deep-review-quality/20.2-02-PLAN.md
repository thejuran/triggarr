**DRQUAL-03 — Narrow tracking exception handler in scheduler.py:**

In `make_search_job` -> `job()` inner try/except (lines 87-91), change:
```python
except Exception as tracking_exc:
```
to:
```python
except (httpx.HTTPError, pydantic.ValidationError, aiosqlite.Error, OSError) as tracking_exc:
```

Add required imports at the top of scheduler.py: `import httpx`, `import pydantic` (if not already present — check first). The `aiosqlite` import already exists.

Rationale: These cover the known failure modes (network errors, validation errors, database errors, filesystem errors). Programming bugs (TypeError, AttributeError, etc.) should NOT be swallowed here — they'll bubble to the outer `except Exception` handler which logs at ERROR level.

**DRQUAL-07 — Fix migration loop to tolerate version gaps:**

In `run_migrations` in db.py, replace the migration loop (lines 64-68):
```python
for version in range(current + 1, target + 1):
    desc, fn = MIGRATIONS[version]
    logger.info("Migrating schema v{old} -> v{new}: {desc}", old=version - 1, new=version, desc=desc)
    await fn(db)
    await set_schema_version(db, version)
```

With:
```python
for version in sorted(MIGRATIONS.keys()):
    if version <= current:
        continue
    desc, fn = MIGRATIONS[version]
    logger.info("Migrating schema v{old} -> v{new}: {desc}", old=version - 1, new=version, desc=desc)
    await fn(db)
    await set_schema_version(db, version)
```

This way, if MIGRATIONS has keys {1, 2, 3, 5} (gap at 4), the loop won't KeyError on version 4.

**DRQUAL-09 — Use async with for cursor in get_schema_version:**

Replace lines 35-36:
```python
cursor = await db.execute("SELECT version FROM schema_version")
row = await cursor.fetchone()
```

With:
```python
async with db.execute("SELECT version FROM schema_version") as cursor:
    row = await cursor.fetchone()
```

This matches the `async with db.execute(...) as cursor:` pattern used everywhere else in db.py.

**DRQUAL-12 — Reinstate at_least_one_search_count model validator:**

In `fetcharr/models/config.py`, add a model validator to `ArrConfig` that ensures at least one of `search_missing_count` or `search_cutoff_count` is > 0 when the app is enabled:

```python
from pydantic import BaseModel, SecretStr, model_validator
```

Add to `ArrConfig`:
```python
@model_validator(mode="after")
def at_least_one_search_count(self) -> ArrConfig:
    """Ensure at least one search count is positive when app is enabled."""
    if self.enabled and self.search_missing_count <= 0 and self.search_cutoff_count <= 0:
        msg = "At least one of search_missing_count or search_cutoff_count must be > 0 when enabled"
        raise ValueError(msg)
    return self
```
