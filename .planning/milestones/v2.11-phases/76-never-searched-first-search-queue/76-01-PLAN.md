**Why the cursor fields stay this plan (HIGH-2 fix):** the six cycle call sites still read `ist["missing_cursor"]`/`ist["cutoff_cursor"]` until Plan 02. If this plan removed those fields from `_default_instance_state()`, a default/new instance running a cycle AFTER this plan's commit but BEFORE Plan 02 would `KeyError` mid-cycle (the scheduler intentionally does not swallow code-bug KeyErrors). So the cursor-field REMOVAL and the call-site rewrite land together in Plan 02's single commit. This plan only ADDS the new fields (additive = no broken checkpoint); the searched-logs sit unused until Plan 02 wires them.

Purpose: `prioritize_batch` is a pure function with a fully-defined I/O contract (design spec §6) and an exhaustive test matrix (spec §8) — the clearest TDD unit in the phase. Writing the unit matrix and the cold-start oracle RED-first locks the behavior-preservation guarantee before any caller depends on it. The additive state fields let Plan 02 flip the runtime over in one coherent commit.
