**base.html:** Replace the `<main>` wrapper (currently line 87-89):

FROM:
```html
  <main class="max-w-7xl mx-auto px-6 py-6">
    {% block content %}{% endblock %}
  </main>
```

TO:
```html
  <div class="max-w-7xl mx-auto px-6 py-6 flex gap-6 items-start">
    <main class="flex-1 min-w-0">
      {% block content %}{% endblock %}
    </main>
    {% block sidebar %}{% endblock %}
  </div>
```

This moves `max-w-7xl mx-auto px-6 py-6` from `<main>` to a wrapper `<div>`. The `<main>` gets `flex-1 min-w-0` (min-w-0 prevents flex child overflow). The `{% block sidebar %}` defaults to empty, so History and Settings pages render full-width with a single flex child (identical layout behavior to before). The `gap-6` provides spacing between main and sidebar when present.

IMPORTANT: Do NOT add `overflow: hidden` or `overflow: auto` to the wrapper div -- this would break `position: sticky` on the rail aside (per research pitfall 1).

**dashboard.html:** Two changes:

1. **Remove** the `{% include "partials/search_log.html" %}` line (currently line 30). Delete the entire line.

2. **Add** a sidebar block AFTER the `{% block content %}` closing. Place it between `{% endblock %}` (the content block end) and any trailing content, or at the end before the script block. The cleanest placement: the sidebar block must be OUTSIDE the content block since Jinja blocks are siblings, not nested.

The dashboard.html structure should become:
```jinja2
{% extends "base.html" %}

{% block title %}Dashboard - Triggarr{% endblock %}

{% block sidebar %}
{% include "partials/activity_rail.html" %}
{% endblock %}

{% block content %}
{# ... existing dashboard content WITHOUT search_log.html include ... #}
{% endblock %}
```

Note: In Jinja2, block order in the child template does not matter -- they map by name. So `{% block sidebar %}` can appear before or after `{% block content %}`. Place it before content for clarity since the sidebar is declared before content in base.html too.

Verify that the `search_log` variable is still passed from the dashboard route (it is -- `"search_log": search_log` in the context dict at routes.py line 293).
