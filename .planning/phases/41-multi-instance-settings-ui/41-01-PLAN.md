**1. Add `validate_instance_name` to `triggarr/web/validation.py`:**
- Function signature: `def validate_instance_name(name: str) -> tuple[bool, str]`
- Strip whitespace, reject empty, reject len > 32, reject `__` in name, reject names not matching `^[a-zA-Z0-9][a-zA-Z0-9 _.-]*$`
- Return (True, "") on success, (False, reason) on failure

**2. Refactor `settings_page()` in routes.py:**
- Replace the "first instance only" loop with a nested dict: `apps[name] = {inst_name: {url, has_api_key, enabled, search_interval, search_missing_count, search_cutoff_count, missing_tag, cutoff_tag} for each instance}`
- Template context `apps` changes from `{radarr: {flat fields}}` to `{radarr: {inst_name: {fields}, ...}, sonarr: {...}}`
- If no instances configured for an app type, pass empty dict (template handles empty state)

**3. Refactor `save_settings()` in routes.py:**
- Replace the "first instance only" form parsing with dynamic field parsing using regex `^(radarr|sonarr)__(.+)__(\w+)$`
- Build `new_config[app][inst_name]` dict from parsed fields
- For each instance: preserve API key when submitted field is empty (same pattern as current)
- Validate each URL with `validate_arr_url`
- Tag fields: read `missing_tag` and `cutoff_tag` from form (empty string = no filter)
- Enable/disable: checkbox field `{app}__{inst}__enabled`, use `form.get(...) == "on"`
- After building config dict, validate with `SettingsModel(**new_config)` (existing pattern)
- Keep existing scheduler update loop, client lifecycle, state entry creation logic (lines 404-483 are already multi-instance aware)
- Use `INSTANCE_FIELD_RE = re.compile(r"^(radarr|sonarr)__(.+?)__(\w+)$")` -- note non-greedy `+?` is NOT needed since `__` is the separator and field names are `\w+` only; use greedy `.+` with the `__(\w+)$` anchor

**4. Add `tag_autocomplete()` endpoint in routes.py:**
- Route: `GET /api/tags/{app_name}/{instance_name}` returning `HTMLResponse`
- Validate app_name in ("radarr", "sonarr"), return empty if invalid
- Get client from `request.app.state.{app_name}_clients` dict
- If no client for instance, return empty HTMLResponse
- Call `client.get_tags()`, return `<option value="{tag.label}">` elements as HTML
- Wrap in try/except, return empty on any error
- Validate instance_name length (max 64, consistent with search_now)

**5. Add `add_instance()` endpoint in routes.py:**
- Route: `POST /api/instance/add` accepting form fields `app_name` and `instance_name`
- Validate instance name with `validate_instance_name()`
- Check instance count < 5 for that app type
- Check no duplicate name exists
- Add new InstanceConfig() with defaults to settings
- Write updated config to TOML via `_atomic_toml_write`
- Reload settings, create state entry
- Return `RedirectResponse` to settings page (303)

**6. Add `remove_instance()` endpoint in routes.py:**
- Route: `POST /api/instance/remove/{app_name}/{instance_name}`
- Validate app_name, check instance exists
- Reject if it would remove the last instance for that app type (at least 0 is fine, but warn if removing all)
- Remove from config dict, write TOML
- Clean up: remove scheduler job, close client, remove state entry
- Return `RedirectResponse` to settings page (303)

**Rewrite `triggarr/templates/settings.html` to render all instances per app type:**

**1. Replace the flat `{% for name, app in apps.items() %}` loop with a nested structure:**
```
{% for app_name, instances in apps.items() %}
  <section> <!-- app type section -->
    <h2>{{ app_name | capitalize }}</h2>
    {% for inst_name, inst in instances.items() %}
      <details open> <!-- accordion per instance -->
        <summary>{{ inst_name }} — {{ "Enabled" if inst.enabled else "Disabled" }}</summary>
        <!-- instance fields -->
      </details>
    {% endfor %}
    <!-- Add Instance button -->
  </section>
{% endfor %}
```

**2. Form field naming convention: `{app_name}__{inst_name}__{field}`**
- Example: `name="radarr__Default__url"`, `name="radarr__4K Radarr__api_key"`
- Double-underscore separator avoids collision with instance names containing single underscores

**3. Per-instance fields to render (inside each `<details>` block):**
- Enabled: checkbox `name="{app}__{inst}__enabled"` with `{% if inst.enabled %}checked{% endif %}`
- URL: text input `name="{app}__{inst}__url"` with value and placeholder
- API Key: password input `name="{app}__{inst}__api_key"` with empty value and masked placeholder
- Search Interval: number input `name="{app}__{inst}__search_interval"`
- Missing Items Per Cycle: number input `name="{app}__{inst}__search_missing_count"`
- Cutoff Items Per Cycle: number input `name="{app}__{inst}__search_cutoff_count"`
- Missing Tag: text input `name="{app}__{inst}__missing_tag"` with `list="tags-{app}-{sanitized_inst}"`, `hx-get="/api/tags/{app}/{inst}"`, `hx-trigger="focus once"`, `hx-target="#tags-{app}-{sanitized_inst}"`, `hx-swap="innerHTML"` + `<datalist id="tags-{app}-{sanitized_inst}"></datalist>`
- Cutoff Tag: same pattern as Missing Tag but for cutoff_tag field

**4. Sanitize instance names for HTML IDs:** Use Jinja2 filter or inline replace: `{{ inst_name | replace(' ', '-') | replace('.', '-') }}` for datalist IDs. The htmx hx-get URL uses the raw instance name (URL-encoded by browser).

**5. Add Instance inline form at bottom of each app section:**
```html
<div class="flex items-center gap-2 mt-4">
    <input type="text" name="instance_name" placeholder="New instance name"
           class="...input styles..." form="add-{{ app_name }}">
    <input type="hidden" name="app_name" value="{{ app_name }}" form="add-{{ app_name }}">
    <button type="submit" form="add-{{ app_name }}"
            class="...button styles...">
        + Add
    </button>
</div>
<form id="add-{{ app_name }}" method="post" action="{{ request.url_for('add_instance') }}"></form>
```
The inline form submits `instance_name` and `app_name` as standard form fields to the `add_instance` endpoint (POST /api/instance/add).

**6. Remove Instance button per instance (inside `<summary>` or at bottom of details):**
```html
<button hx-post="{{ request.url_for('remove_instance', app_name=app_name, instance_name=inst_name) }}"
        hx-confirm="Remove instance '{{ inst_name }}'? This cannot be undone."
        hx-target="body" hx-swap="outerHTML"
        class="text-red-400 hover:text-red-300 text-sm">
    Remove
</button>
```

**7. Empty state:** When `instances` dict is empty for an app type, show a message: "No instances configured. Add one below."

**8. Tag field help text:** Below each tag input: "Leave empty to search all items. Autocomplete loads from the *arr instance when focused."

**9. Styling:** Use existing Tailwind classes from the current template. Accordion uses `<details>/<summary>` with `bg-triggarr-card rounded-lg border border-triggarr-border`. Instance fields use the existing `grid grid-cols-1 md:grid-cols-2 gap-4` layout. Tag fields go in a separate row below the grid.
