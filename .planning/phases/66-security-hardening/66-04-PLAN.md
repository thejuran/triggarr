<objective>
Migrate every inline event-handler attribute (`onclick=`, `onchange=`) in
`triggarr/templates/` to `addEventListener` calls placed inside the existing
nonced inline `<script>` blocks (the scripts already exist in each template;
this plan does not add new `<script>` blocks). This is **step 1 of a 2-step
SEC-01 migration** — `'unsafe-inline'` is NOT removed from CSP `script-src`
in this plan (plan 66-05 does that). Running 66-04 alone is a no-op for
browser behavior (handlers fire identically) but lands safely on a green
codebase before the CSP tightening that depends on this work.

Purpose: SEC-01 (part 1 / 2). Per RESEARCH Pitfall 1 (THE single biggest risk
in Phase 66), CSP Level 3 nonces apply ONLY to `<script>` elements, NEVER to
event-handler attributes. Today there are 13 inline `on*=` attributes across
5 template files plus 1 partial. Dropping `'unsafe-inline'` from `script-src`
in plan 66-05 will block all of them — every page becomes silently broken in
production. This plan removes them first so 66-05 can drop `'unsafe-inline'`
without breakage.

Per D-05 (revised): the exhaustive inventory is 13 attributes:
- `base.html:31` (openChangelog), `base.html:104` (closeChangelog on backdrop), `base.html:108` (closeChangelog)
- `setup.html:60` (copyApiKey)
- `settings.html:100` (updateMethodWarning), `settings.html:152` (event.stopPropagation)
- `partials/security_apikey.html:18,29,41,54,58` (toggleApiKeyVisibility, copyApiKey, showRegenConfirm, confirmRegen, cancelRegen)
- `partials/log_viewer.html:19` (onchange — level filter), `partials/log_viewer.html:28` (toggleLogPause), `partials/log_viewer.html:32` (toggleLogExpand)

The hard challenges are the two partials:
1. `partials/log_viewer.html` is hx-swapped via `outerHTML` every 5 seconds — element references inside the partial are replaced after every poll. Solution: replace inline handlers with `data-action="log-expand"` / `data-action="log-pause"` / `data-action="log-level"` markers, and add a `bindLogViewerControls(viewer)` helper in the (non-swapped) dashboard.html `<script>` that re-queries and re-attaches listeners on every `htmx:afterSwap` event targeting `#log-viewer`. The existing `htmx:afterSwap` listener at dashboard.html:52-69 already runs on every swap — we extend it with the rebind call.
2. `partials/security_apikey.html` is hx-swapped via `innerHTML` into the parent `#apikey-section` (settings.html:126-130). The parent stays; the inner content changes. Solution: a single delegated click listener on `#apikey-section` (lives in settings.html `<script>`) reads `event.target.closest('[data-action]')` and dispatches to the matching handler function. Delegated listener survives all `innerHTML` swaps.

This plan is `type: execute` (mechanical template edits + JS function bodies),
NOT `type: tdd`. RED→GREEN→REFACTOR offers no value for HTML attribute moves;
the verification gates are:
- a grep assertion that ZERO `on(click|change|submit|load|blur|focus|keydown|keyup|input)=` attributes remain in `triggarr/templates/`
- a smoke test that exercises the log viewer partial endpoint to confirm
  the rendered HTML contains the new `data-action` attributes
- the existing tests/test_log_viewer.py continues to pass (the partial render
  is asserted there; we extend one test to assert `data-action` presence)

**Dependency rationale (66-04 depends_on: [66-02]):** Plan 66-02 modifies
`AuthMiddleware._handle_basic_auth` in `triggarr/web/middleware.py`. Plan
66-04 does NOT touch middleware.py. The dependency exists ONLY because
plan 66-05 (Wave 3) modifies `SecurityHeadersMiddleware` in the same file
and 66-05 depends on 66-04 — by chaining 66-04 after 66-02 we keep the
linear timeline tidy and avoid any chance of two open branches both touching
middleware.py. Since 66-04 itself touches no Python source modified by
66-02, the actual merge order does not matter for correctness; this
dependency is a scheduling constraint.

Output:
- 6 template files with `on*=` attributes removed and matching event bindings
  added (or markers + delegated listeners for the two partials).
- `tests/test_log_viewer.py` extended with one assertion that the log_viewer
  partial render contains `data-action="log-pause"` and `data-action="log-expand"`
  (verifies the migration in the partial endpoint).
- A repository-wide grep gate that confirms zero `on*=` attributes remain in
  `triggarr/templates/` (negative assertion in acceptance criteria).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Jinja-rendered HTML → browser DOM | Template content is server-controlled; the only attacker-influence vector is interpolated values via `{{ ... }}` already protected by Jinja autoescape (verified at routes.py:62) |
| Inline event-handler attribute → CSP `script-src` policy | CSP Level 3 nonces do NOT extend to event-handler attributes; this plan's migration is the only way to make `'unsafe-inline'` removal in 66-05 safe |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-01 | Tampering (XSS via inline scripts) | Templates currently emit inline event-handler attributes that would execute under any `'unsafe-inline'` policy; an attacker who could inject content into a template render could inject a handler attribute. | mitigate (precursor) | This plan removes ALL `on*=` attributes from `triggarr/templates/`, enabling plan 66-05 to drop `'unsafe-inline'` from `script-src`. Without 66-04, the 66-05 CSP tightening would silently break every page. |
| T-66-01b | Tampering (XSS via swapped partial) | The hx-swapped partials (#log-viewer outerHTML every 5s, #apikey-section innerHTML on regen) could re-introduce inline handlers via a future template edit | mitigate (process) | The repo-wide grep gate in acceptance criteria runs in CI on every PR — any future inline handler added to ANY template will be caught before merge. |
| T-66-01c | Denial of Service (handler not bound after swap) | If `bindLogViewerControls` is not called on every htmx:afterSwap, the log viewer controls (expand/pause/level filter) silently stop working after the first 5s poll — the page appears broken | mitigate | bindLogViewerControls is hooked into the EXISTING htmx:afterSwap listener (dashboard.html:52-69) which is known to fire on every swap. The browser-smoke checkpoint in plan 66-05 verifies the runtime behavior. |
| T-66-01d | Repudiation | A delegated listener on #apikey-section that fails to filter `event.target.closest('[data-action]') !== null` could trigger on every click in the section (including form-submission clicks), breaking the regen flow | mitigate | Delegated listener body explicitly checks `if (!t || !section.contains(t)) return;` before dispatching on `t.dataset.action`; the `switch` falls through (no default) for unrecognized actions. |
