<objective>
Complete the SEC-01 migration by wiring a per-request CSP nonce through
`SecurityHeadersMiddleware` and a Jinja2Templates `context_processors`
callable, then dropping `'unsafe-inline'` from the CSP `script-src` directive
and tagging every inline `<script>` block in templates with
`nonce="{{ csp_nonce }}"`. The middleware generates the nonce in
`dispatch()` BEFORE `call_next` (so the template render can read it from
`request.state`), and the same `dispatch()` composes the response CSP header
using the same nonce value AFTER `call_next` returns.

Per RESEARCH Pattern 1 and Pitfall 7 (middleware order matters):
- Nonce is set on `request.state.csp_nonce` as the FIRST line of `dispatch()`
- `await call_next(request)` runs; the route handler renders templates; the
  context processor reads `request.state.csp_nonce` and exposes it as
  `{{ csp_nonce }}` in every render
- CSP header is composed using the SAME nonce value on the response side

Per RESEARCH Pitfall 5: tests asserting nonce parity use ONE request, extract
the nonce from the response's CSP header, and assert it appears in the same
response's HTML body. Two separate requests would have two different nonces.

Per RESEARCH Pitfall 8: the context_processor MUST be a synchronous callable
(`def`, not `async def`) — Jinja2Templates expects sync.

Per D-04: `style-src` keeps `'unsafe-inline'` (Tailwind utility output is
fine). Only `script-src` is tightened.

**Hard prerequisite (depends_on: [66-04]):** Plan 66-04 must be merged first.
If ANY inline `on*=` attribute remains in `triggarr/templates/`, dropping
`'unsafe-inline'` will silently break every page in production. Plan 66-04's
acceptance gate (`grep -rnE 'on(...)=' triggarr/templates/` returns 0) is
re-verified in this plan as a sanity check.

**Dependency on 66-02:** Plan 66-02 already modified
`AuthMiddleware._handle_basic_auth` in the same `triggarr/web/middleware.py`
file. This plan modifies `SecurityHeadersMiddleware` (a different class in
the same file). The 66-02 → 66-05 dependency ensures the two edits land
sequentially with no merge conflict.

**checkpoint:human-verify is REQUIRED in this plan.** Per RESEARCH
"Validation Architecture > Manual-Only Verifications" and VALIDATION.md
"Manual-Only Verifications": `TestClient` does NOT enforce CSP — pytest
tests can only assert the header VALUE and the rendered HTML contains the
right substrings; they cannot assert that the browser actually accepts the
scripts under the new policy. A blocking human checkpoint at the end of this
plan asks the operator to run the local Docker build, open the four primary
pages in Chrome with DevTools console open, and confirm zero CSP-violation
console entries. This is the only honest acceptance for SEC-01.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Attacker-controlled HTML injection point → rendered template | Even with Jinja autoescape, a `{{ ... }}` site that emits content into a `<script>` block (or a `srcdoc` iframe, etc.) could host attacker payload. Nonce-based CSP prevents the payload from executing because the attacker cannot guess the per-request nonce. |
| Middleware request-down phase → request.state.csp_nonce | Internal-only; tampering would require code execution on the server, in which case CSP is already moot. |
| Response CSP header → browser policy enforcement | The browser is the policy enforcer. TestClient does not — manual verification is required. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-01 | Tampering (XSS via injected inline `<script>`) | A template `{{ ... }}` interpolation site that fails autoescape (e.g. via the `\| safe` filter or a json-script interpolation) would let an attacker inject `<script>alert(1)</script>` | mitigate | After this plan, `script-src 'self' 'nonce-<value>'` blocks any inline `<script>` whose nonce attribute does not match the per-request value. The attacker cannot guess the 128-bit `secrets.token_urlsafe(16)` nonce. The legitimate inline scripts all carry the correct nonce via `{{ csp_nonce }}`. |
| T-66-01e | Tampering (nonce reuse across requests) | If the nonce were cached or set as a Jinja2 global instead of a per-request context_processor, every page would share the same value — once leaked, the attacker could spoof it | mitigate | Nonce is generated INSIDE `dispatch()` per request via `secrets.token_urlsafe(16)`. `test_csp_nonce_changes_per_request` regression-guards against accidental caching. The context_processor reads `request.state` (per-request scope), NOT a Jinja `globals` (process-wide). |
| T-66-01f | Information Disclosure (CSP header leaks middleware behavior) | The CSP header advertises 'self' + a nonce — an attacker can read the policy but cannot bypass it | accept | CSP is a defense-in-depth mechanism; the policy itself is public by design. |
| T-66-01g | Denial of Service (broken page from CSP mismatch) | If the nonce in the header does not match the nonce in the rendered script tag, the page silently breaks — appears as "buttons don't work" to the user | mitigate | (a) Both sides read from `request.state.csp_nonce`, set in the SAME middleware before `call_next` (Pitfall 7). (b) `test_csp_nonce_matches_html_script_tag` asserts header-body parity. (c) Manual browser smoke check (Task 5) verifies the runtime contract on the four primary pages. |
| T-66-SC | Tampering (supply chain) | No new packages installed in this phase per RESEARCH "Package Legitimacy Audit" | n/a | No installs to gate. |
