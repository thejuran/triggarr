<objective>
Add a Pydantic v2 `@field_validator('url')` to `InstanceConfig` in
`triggarr/models/config.py` that rejects any URL whose query string contains an
`apikey=` parameter (case-insensitive, including the empty-value variant
`?apikey=`). The validator raises `ValueError` carrying the exact D-08 error
message, which Pydantic wraps into `ValidationError` — the existing settings POST
handler at `routes.py:565-569` already catches `pydantic.ValidationError` and
redirects with a logged warning.

Purpose: SEC-02. Today, a user pasting a full *arr connection string with the
embedded API key (e.g. `http://radarr:7878/?apikey=abc123`) would silently
persist that secret into `triggarr.toml`, where it would also be picked up by
log redaction late (after the secret was already on disk). The validator runs
at model construction time — BEFORE the search lock is acquired and BEFORE
`_atomic_toml_write` runs (verified at routes.py:566 vs 575) — so the rejection
happens before the secret reaches the filesystem.

Scope is narrow per D-07: only `apikey=` keys (any case) are rejected. Other
query parameters (e.g. `?base=/sonarr`, `?token=foo`) remain valid because
legitimate reverse-proxy / subpath setups depend on them.

Output:
- `triggarr/models/config.py` — new `@field_validator('url')` classmethod
  `reject_apikey_in_url` on `InstanceConfig`, plus the matching import of
  `field_validator` and `parse_qsl`/`urlparse`.
- `tests/test_config.py` — parametrized accept-list and reject-list tests that
  cover D-07 case variants and the D-08 empty-value variant.
</objective>
