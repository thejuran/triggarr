<objective>
This plan covers BOTH halves of the search_history bound contract for v2.8:

1. **SAFETY-01 (resolved-row trim — existing implementation)**: The production SQL at `triggarr/db.py:339-350` already trims resolved rows (`outcome != 'searched'`) after every insert to keep their count ≤ `max_history_rows`. This plan adds (a) an expanded docstring on `insert_search_entry` making the guarantee explicit and operator-readable, and (b) a soak test driving 2× max_rows inserts to prove the cap holds at steady state. No SQL change for SAFETY-01.

2. **SAFETY-01b (pending-row cap — NEW implementation, per Codex adversarial review F1, User Decision Path A)**: Today, pending rows (`outcome='searched'`) are intentionally exempt from the resolved-row trim because they represent in-flight tracking that the search engine wants to resolve. The original requirement language ("the table never exceeds `max_history_rows`") therefore had a real failure mode: if Sonarr/Radarr is unreachable for an extended period, the tracker stalls and every search cycle adds more pending rows that are never resolved. The Codex review surfaced this as F1; the user chose Path A: narrow SAFETY-01 to resolved rows AND add a new bound `SAFETY-01b` that caps pending rows at `2 × max_history_rows` by **rejecting new pending inserts** (not evicting old — eviction loses tracking semantics) with a logged WARNING. This plan ships that pending cap via a TDD task triple (RED failing test → GREEN implementation → REFACTOR for clarity/constants).

Purpose: Closes SAFETY-01 AND the newly-added SAFETY-01b. The pending cap mitigates the T-64-05 threat scenario: Sonarr/Radarr unreachable for extended period → every search cycle adds pending rows → table grows past `max_history_rows` → eventual disk exhaustion or query slowdown. Rejecting (rather than evicting) preserves tracking semantics for the entries already in flight, which was the original concern in the Open Question that drove the SAFETY-01 deferral.

Output: Changes to `triggarr/db.py` — one expanded docstring, one new exception class `PendingCapExceeded`, one new module constant `PENDING_CAP_MULTIPLIER = 2`, one new pending-count guard in `insert_search_entry`, one new `logger.warning` call when the cap is hit. Changes to `tests/test_db.py` — one soak test for SAFETY-01 (existing scope) AND three new tests for SAFETY-01b (RED, GREEN, REFACTOR verification). No schema migration. No SQL change to the resolved-row trim.

```python
async def insert_search_entry(
    db: aiosqlite.Connection,
    app: str,
    queue_type: str,
    item_name: str,
    outcome: str = "searched",
    detail: str | None = None,
    item_id: int | None = None,
    season_number: int | None = None,
    missing_count: int | None = None,
    instance_id: str = "Default",
    max_rows: int = 1000,
) -> None:
    """Insert a search log entry and prune resolved rows beyond *max_rows*.

    Args:
        db: aiosqlite connection (shared lifespan-scoped connection).
        app: 'Radarr' | 'Sonarr' | 'Lidarr'.
        queue_type: 'missing' | 'cutoff' | 'tracking'.
        item_name: Display string for the row.
        outcome: 'searched' (pending) | 'grabbed' | 'failed' | 'expired' (resolved).
        detail: Optional human-readable detail.
        item_id, season_number, missing_count: optional structured fields.
        instance_id: Instance label (default 'Default' for v2.2 compat).
        max_rows: Maximum resolved rows to keep (pending rows are exempt).
    """
    timestamp = datetime.now(timezone.utc).isoformat()
    await db.execute(
        "INSERT INTO search_history (timestamp, app, queue_type, item_name, outcome, detail, "
        "item_id, season_number, missing_count, instance_id) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
        (timestamp, app, queue_type, item_name, outcome, detail,
         item_id, season_number, missing_count, instance_id),
    )
    # Tracking-aware pruning (DEBT-03): only prune resolved rows, preserve pending (outcome='searched')
    await db.execute(
        """
        DELETE FROM search_history
        WHERE COALESCE(outcome, 'searched') != 'searched'
        AND id NOT IN (
            SELECT id FROM search_history
            WHERE COALESCE(outcome, 'searched') != 'searched'
            ORDER BY id DESC LIMIT ?
        )
        """,
        (max_rows,),
    )
    await db.commit()
```
