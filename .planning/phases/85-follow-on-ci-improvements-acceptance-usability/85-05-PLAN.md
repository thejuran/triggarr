<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author -> review-acceptance.yml | A PR's workflow file decides which gate commit runs for that PR |
| Operator CLI -> repository variables | Claude writes registers with the owner's gh credentials |
| Repository variable -> gate | Whole-value variables shared by every PR |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-85-12 | Tampering | Concurrent PRs overwriting each other's register entries | mitigate | PR+head keyed slices; read-back verification; missing-entry gate failure; serialization rule documented (85-17) because variables lack compare-and-swap |
| T-85-13 | Spoofing | One PR's disposition satisfying another PR | mitigate | Lookup only by registerKey(prNumber, head); test with another PR's slice at the same head |
| T-85-14 | Elevation of privilege | Pin bump lets a PR run modified gate code | mitigate | Pin points to a reviewed commit on this branch; disclosed as self-graded; independent Codex inspection required before acceptance |
| T-85-15 | Tampering | Command injection via CLI arguments | mitigate | Integer/40-hex validation and allowlisted variable names before any execFileSync argument-array call; tested with an injected exec |
| T-85-16 | Repudiation | Approval on a draft PR then repeat approval | mitigate | Gate rejects drafts; readiness tool (85-14) shows draft state before approval is requested |
</threat_model>
