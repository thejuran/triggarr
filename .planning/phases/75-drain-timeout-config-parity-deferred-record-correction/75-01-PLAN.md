<objective>
Lay the foundation for the drain-timeout config knob: add the bounded, finite-only
`shutdown_drain_timeout` field to `GeneralConfig` (D-01) and add the `safe_float`
parse-and-clamp helper to `validation.py` (D-03). Both are consumed by the Wave 2 settings
round-trip (Plan 02) and the field is consumed by the Wave 2 scheduler refactor (Plan 03).

Purpose: Establish the persisted config field and the float-honest form parser before any
consumer wires them — the interface-first ordering that lets Plans 02 and 03 build against
fixed contracts without exploring the codebase. Both surfaces must guarantee a FINITE drain
value: `nan`/`inf` are NOT rejected by `float()` and survive a `max(value, 1.0)` clamp
(`max(nan, 1.0) == nan`, `max(inf, 1.0) == inf`), which would silently disable or unbound the
drain — exactly the "typo disabling the drain" failure §4.2 of the spec defends against.
Output: One new finite-only `GeneralConfig` field, one new non-finite-rejecting `safe_float`
helper, plus their tests.
</objective>

From triggarr/models/config.py (GeneralConfig, config.py:122-136) — the bounded-field analog:
```python
# SAFETY-03: bounded 1..100 to defend against typos at config edit time
max_consecutive_failures: int = Field(default=5, ge=1, le=100)
```
`Field` is already imported in this module (used by `max_consecutive_failures`). The new field
is a `float` (like `request_timeout: float = 30.0`, config.py:129) with a `ge=1.0` lower bound,
NO upper bound on the model (D-01 — the form clamp supplies the UI ceiling), and
`allow_inf_nan=False` so a TOML/config `inf` or `nan` is rejected at construction. NOTE
(confirmed in the project venv): `Field(ge=1.0)` ALONE accepts `+inf` (Pydantic v2 default
`allow_inf_nan=True`) — `ge=1.0` rejects `nan` but NOT `inf`. `allow_inf_nan=False` rejects
`inf`, `nan`, AND `-inf` cleanly, closing that gap.

From triggarr/web/validation.py (safe_int, validation.py:179-199) — the helper analog:
```python
def safe_int(value: str | None, default: int, minimum: int, maximum: int) -> int:
    if value is None or value == "":
        return default
    try:
        n = int(value)
    except (ValueError, TypeError):
        return default
    return max(minimum, min(maximum, n))
```
`safe_float` is a structural clone with `float()` in place of `int()`, PLUS a non-finite guard:
`float("nan")`, `float("inf")`, `float("-inf")` all parse WITHOUT raising, and the clamp does NOT
neutralize them (`max(nan, 1.0) == nan`, `max(inf, 1.0) == inf`). So after coercion, `safe_float`
must reject non-finite values with `math.isfinite(n)` and return `default` — exactly as it does
for malformed strings. Signature this plan exports for Plan 02 to import:
`def safe_float(value: str | None, default: float, minimum: float, maximum: float) -> float`
