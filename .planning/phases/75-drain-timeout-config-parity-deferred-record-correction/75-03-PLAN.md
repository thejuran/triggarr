<objective>
Refactor the scheduler shutdown drain so the timeout is resolved from the configured value at
shutdown time with the env var overriding it (D-04/D-05/D-06), delivering the precedence half of
CFG-04. This is the one real wiring change in the phase: (1) make `_read_shutdown_drain_timeout`
accept a `configured` default, apply `TRIGGARR_SHUTDOWN_DRAIN_TIMEOUT` on top with a `>= 1.0`
clamp on both sources, AND guarantee the result is FINITE (a `nan`/`inf` from either source —
which `float()` parses without raising and which survives `max(value, 1.0)` — must fall back to a
finite default); and (2) resolve a single local `drain` at the top of the shutdown-drain block
and replace every `_SHUTDOWN_DRAIN_TIMEOUT` reference in the shutdown path with it.

The refactor is behavior-preserving for the shutdown mechanism (`asyncio.timeout()`, WR-01) —
only the timeout VALUE source changes. The full existing suite must stay green.

Purpose: Remove the import-time-staleness footgun (the drain was read once at module import) so
the operator's configured value (and env override) is honored at actual shutdown time, where
`app.state.settings` is already in scope — and guarantee `asyncio.timeout(drain)` always receives
a finite value (an `inf` would never bound the drain; a `nan` would time out immediately —
either way the drain is effectively disabled, the failure the >=1.0 clamp was meant to prevent).
Output: A config-aware, finite-guaranteed helper, a local-resolved `drain` in the shutdown block,
precedence-matrix tests (including non-finite), and a migrated holder-identity test.
</objective>

Target signature: `def _read_shutdown_drain_timeout(configured: float = 60.0) -> float`.

itself is somehow non-finite, fall back to the module default 60.0 — so the helper NEVER returns
nan/inf. Finally return `max(value, 1.0)` so the clamp applies to BOTH sources. Add
`import math` to the module (ruff I). Keep the existing stop_grace_period deployment-guidance
docstring tail.

| T-75-07 | Denial of Service | drain resolution (both sources) | mitigate | `max(value, 1.0)` clamps BOTH the configured value and the env override; a 0/negative value cannot disable the drain — the in-flight search cycle still gets a bounded grace window before SIGKILL |
| T-75-07b | Denial of Service | non-finite drain value | mitigate | The `math.isfinite` guard rejects a non-finite resolved value (env nan/inf/-inf, or a non-finite configured value) and falls back to a finite default. Without it: `asyncio.timeout(inf)` never bounds the drain (waits until SIGKILL — drain effectively disabled), and `asyncio.timeout(nan)` can time out immediately (drain effectively disabled). `max(nan,1.0)==nan` / `max(inf,1.0)==inf` means the clamp alone does NOT neutralize them — closing the "typo disabling the drain" vector end-to-end |
| T-75-08 | Denial of Service | malformed env var at shutdown | mitigate | A non-float TRIGGARR_SHUTDOWN_DRAIN_TIMEOUT falls back to the configured default (caught via (ValueError, TypeError)) instead of crashing the shutdown path |

The configured value is additionally finite-bounded at the model (75-01 allow_inf_nan=False) |
| T-75-10 | Information Disclosure | shutdown drain logging | accept | The drain logs the timeout value and the holder job_id/elapsed only — no token/hash/secret/PII; SecretStr discipline unaffected (no secret fields in scope) |
