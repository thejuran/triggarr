<objective>
Make instance removal safe against a failed settings write and against a concurrent removal, and give the server side of the user-facing failure message.

Feature: `remove_instance` (triggarr/web/routes.py) currently deletes the instance from the live settings dict before writing the file, so a failed write leaves live settings, the scheduler job and the client registry disagreeing. Reorder it to read-under-lock -> build -> write -> swap (D-02), turn a write failure into the fixed D-05 message with exactly one error log entry (CONSIST-02 server side, D-07), and make every post-save tidy-up step independent so one failure never leaves another step undone (D-15, D-16).

Purpose: CONSIST-01 and the server half of CONSIST-02. Plan 87-02 wires the row-level display in settings.html on top of this response contract.
Output: reordered `remove_instance`, a default-preserving `log_failure` flag on `_atomic_toml_write`, new regression tests in tests/test_web.py and tests/test_config.py, 2-3 commits per task (test -> feat/fix -> optional refactor).

Branch: work only on the current branch `phase-87-settings-state-file-safety`. Commit directly on it (no worktree commits, no push, no PR).
</objective>
