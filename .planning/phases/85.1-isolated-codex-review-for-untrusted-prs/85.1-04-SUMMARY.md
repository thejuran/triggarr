### Auto-fixed Issues

**1. [Rule 1 - Bug] RED-phase test anchored on the wrong occurrence of the fence markers**
- **Found during:** Task 2 (GREEN), running `tests/test_codex_review_contract.py` against the newly written prompt
- **Issue:** `test_inspection_prompt_states_no_tools_and_untrusted_input` (written in Task 1) used `prompt.index(...)` to find `{{INPUT_FENCE}}-BEGIN`/`{{INPUT}}`/`{{INPUT_FENCE}}-END`, but the prompt's own explanatory sentence ("The complete review input is the text between the line `{{INPUT_FENCE}}-BEGIN` and the line `{{INPUT_FENCE}}-END`...") also contains those exact substrings earlier in the text, so the test anchored on the prose mention instead of the real trailing fence.
- **Fix:** Switched to `rindex` (from the end) to anchor on the trailing, standalone occurrence.
- **Cost if wrong:** Low -- the test would have falsely failed (or, with different prompt wording, falsely passed) on the real fence placement; no product/runtime code is affected, only this test's own correctness.
- **Files modified:** `tests/test_codex_review_contract.py`
- **Verification:** `uv run pytest tests/test_codex_review_contract.py -q` -- 27 passed.
- **Committed in:** `6f95f45` (Task 2 GREEN commit)

**2. [Rule 1 - Bug] Status-row test collided with the BM review table's own Status row**
- **Found during:** Task 2 (GREEN), running `tests/test_review_checkpoint_record.py`
- **Issue:** `test_status_row_defines_inspection_only_completeness` (written in Task 1) used the existing shared `_codex_table_line("Status")` helper, which returns the *first* line in the whole document starting with `| Status |` -- that is the unrelated `### BM review` table's Status row, not the `### Codex` table's Status row this test needs.

- **Cost if wrong:** Low -- the test would silently check the wrong table's unrelated row and could pass or fail for the wrong reason; no risk to doc content itself.
- **Files modified:** `tests/test_review_checkpoint_record.py`
