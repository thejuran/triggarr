# Phase 85.1 Plan 09: Per-Attempt Completion Gate and Standalone Boundary Verification Summary

**Per-attempt completion gate (`completion_gate()`/`--completion-gate`) that reads exactly one attempt's records with no glob (B18), plus `--verify-boundary [--with-probes]` for pre-merge isolation-boundary evidence against the real built image with no PR and no review, probes strictly supplementary and downgrade-only.**

## Accomplishments

- `completion_gate(out_prefix)` decides COMPLETE per attempt: `_OUT_PREFIX_RE` (same shape as `acceptance-readiness.cjs`'s `OUT_PATH_RE`) refuses anything not matching the phase codex output-path shape before any filesystem read; every record is read via `safe_read_regular_file()` (refusing a symlink); meta's `review_mode`/head/attempt must match the prefix; boundary must be `verified` and bound to the same head/attempt; status must be `complete` and bound (`inspected_head`/`inspected_base`); grader provenance must be `established`, `base_on_main`, and `grader_source == "trusted-origin-main"`; `.base-status.json` is required and checked only when `audited_inputs_changed_in_diff` is non-empty. `--completion-gate PREFIX` prints `{"gate": "pass"|"fail", "prefix": ..., "reasons": [...]}` and exits 0/3.
- `_build_tool_parser()`: a second, narrower parser (`--completion-gate PREFIX` / `--verify-boundary` mutually exclusive and required, `--with-probes` only valid with `--verify-boundary`) that `main()` routes to only when argv contains one of those two flags, leaving `_build_parser()` (the review parser) completely unweakened and unable to accept either tool flag.
- `verify_boundary_main(*, with_probes, command_runner=run_command)`: runs only the deterministic checks `verify_isolation_boundary()` already performs (`run=None`), under one `ContainerLedger` whose `on_cleanup_problems` finalizer is `_print_boundary_cleanup_escalation`; prints the public (non-underscore) boundary keys as JSON with every occurrence of the per-run scratch path replaced by `<SCRATCH>`; writes nothing under REPO_ROOT; exits 0 only when the final verdict is verified, 3 otherwise.
- `run_boundary_probe()`/`PROBE_PROMPT_TEMPLATE`: plants two executable scripts and a canary file (each holding a random `secrets.token_hex(16)` value) in its own scratch dir, outside every container mount; asks Codex via the fixed prompt to run them and read the canary by absolute host path; reuses `launch_in_verified_container()` with `run=None`; a disallowed item type in the resulting `.jsonl` or a planted token surfacing in the transcript downgrades the verdict with a named reason, and a sign-in refresh mid-probe surfaces the existing D-11 reason; absence of findings only ever produces `"supplementary: no tool use or token observed (not proof)"`, never a positive confirmation.
- `_print_boundary_cleanup_escalation()`: prints the unverified verdict with every cleanup problem to stdout before an in-flight `KeyboardInterrupt`/`SystemExit`/probe-preparation failure re-raises, never raises itself, and never reads anything the container wrote.
- Fixed two bugs in the existing (Plan 85.1-08) launch seam, both required for the probe to run with no `ReviewRun`: `launch_in_verified_container()`'s `jsonl_path` parameter was accepted but never actually used (`_stream_events` always wrote to `run.output(".jsonl")` instead); and `verify_isolation_boundary()`/`launch_in_verified_container()` both required a real `ReviewRun`. `_stream_events()` now takes `jsonl_path` explicitly, and both functions accept `run: ReviewRun | None`.
