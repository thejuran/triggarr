## Warnings

### WR-01: A collaborator who pushes to a Dependabot branch bypasses the SA-04 extension

**File:** `tests/codex_review_run.py:1117-1129` (`ci_independence_rule_applies`), `.github/scripts/acceptance-readiness.cjs:52-56` (`ciIndependenceRuleApplies`)

**Issue:**
- **What the exemption checks:** it is decided from `author_login` / `author_is_bot`. Those come from `gh pr view --json author`, which is the account that **opened** the PR. It is not the author of the commits being reviewed.
- **Who can push to bot branches:** Dependabot branches (`dependabot/...`) live in this repository, so every account with write access can push to them.
- **How the bypass works:** a non-owner collaborator, the exact actor SA-04 was ruled to cover, pushes a commit to an open Dependabot PR. The commit edits `.github/os-scan-exceptions.json` or `.github/scripts/os-scan-gate.cjs`.
- **What follows:**
  - The PR author is still `app/dependabot` with `is_bot: true`, so the rule does not apply.
  - `ci.yml` runs the head's own gate files and posts a green "CI ready".
  - The runner reviews the head as if its CI were independent, and `_ci_evidence_text` tells Codex that CI passed.
  - The readiness check shows `ok` instead of `NOT INDEPENDENT`.

**The exemption is broader than the ruling:** the ruling was "Dependabot exempt", but the code exempts every recognised bot, meaning any GitHub App with contents-write on the repository, including `github-actions[bot]`. Today no workflow here opens PRs, so this part is latent.

**Fix:** Exempt a bot-authored same-repository head only when every commit in `merge-base..head` was written by that bot. Read `gh api repos/{REPO}/pulls/{N}/commits --paginate --slurp` and require all of these for each commit:
- `author.login` and `committer.login` are the bot's login (or `web-flow` as committer);
- `commit.verification.verified` is `true`.

Any other commit makes the rule apply. Treat a read failure as covered (fail closed). Mirror this in `ciIndependenceRuleApplies` (readiness already has the PR number), and add a parity row. If the owner also wants to match the ruling literally, narrow the exemption to the Dependabot identity (`app/dependabot` / `dependabot[bot]`) rather than any bot.

```python
def ci_independence_rule_applies(pr_info):
    if pr_info.get("is_cross_repository"):
        return True
    login = pr_info.get("author_login") if isinstance(pr_info.get("author_login"), str) else ""
    if _is_recognised_bot(login, pr_info.get("author_is_bot")):
        return not pr_info.get("all_commits_by_author_bot", False)   # new, fail closed
    return login not in TRUSTED_AUTHORS
```

### IN-01: When the `.github/` change set cannot be read, the checklist says the head changes `.github/`, and the git error is dropped

**File:** `.github/scripts/acceptance-readiness.cjs:310-318`, `593-595`
**Issue:**
- **What happens:** `ciDefinitionsChanged === null` (the git diff failed) gives the same fixed detail as a real change: "this fork or non-bot untrusted head changes files under .github/".
- **Why it matters:** the owner reads a factual claim that git never established.
- **The dropped error:** the `catch {}` throws the error away. That goes against the project's rule to log a swallowed exception, at minimum.

**Fix:** Keep the error message. When the value is `null`, render "could not determine whether files under .github/ changed (<error>); treated as not independent".

### IN-02: The attempt-1 fallback exception trusts the status file and does not cross-check the head

**File:** `.github/scripts/codex-fallback.cjs:350`, `.github/scripts/acceptance-readiness.cjs:162-168`
**Issue:**
- **What it accepts:** `ciNotIndependent` comes only from the `.status.json` reason string.
- **What readiness already knows:** whether the rule covers this head, and whether `.github/` changed (`ciDefinitionsChanged`). Neither is required for the exception.
- **What slips through:** a stale or hand-edited attempt-1 stop record for a head the rule does not cover, such as Dependabot, or for a head whose `.github/` did not change, opens the fallback without the usual retry.
- **Why this is Info:** the records are written by the local operator, at the same trust level as the person recording the fallback.
**Fix:** In `readiness()`, set `codexStatus.ciNotIndependent` only when `ciIndependenceRuleApplies(...)` holds and `ciDefinitionsChanged !== false`.

### SA-05: The trusted path also decides trust by who opened the PR, not by who wrote its commits

**Where:** `tests/codex_review_run.py:639-650` (`_verify_trust_pr`), `.github/scripts/acceptance-readiness.cjs:40-43` (`headTrustFor`)
**Why excluded:**
- **Same root cause as WR-01:** a write collaborator can push commits to a same-repository branch whose PR the owner opened.
- **Why it is set aside:** the trusted-path trust model predates this phase's round-3 changes and is outside the requested focus.
**Effect if left as is:**
- **What it allows:** the head is classed `trusted`, so `pytest` runs collaborator-written code locally on the owner's machine, with the owner's environment. This is the boundary Phase 85.1 exists to protect.
- **Today:** this cannot happen, because the owner is the only write collaborator.
- **When it starts to matter:** the moment a second write collaborator is added, which is the premise of the SA-04 ruling.
**Needs:** a ruling. Options:
- (a) Accept, and state in the contract that trust assumes no other write collaborators.
- (b) Also require every commit in `merge-base..head` to be authored and committed by a `TRUSTED_AUTHORS` login. This uses the same commits check as the WR-01 fix, so both could share one helper.
