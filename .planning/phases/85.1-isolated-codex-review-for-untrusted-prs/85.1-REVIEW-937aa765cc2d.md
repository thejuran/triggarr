## Set aside (needs ruling)

### SA-01: setup-uv installs whatever uv is latest at run time (pre-existing, not changed by this rollup)

**Where:** `.github/workflows/ci.yml:23,103,155,240,256,298` (none pass `version:`; pyproject.toml has no `[tool.uv] required-version`)
**Why excluded:** The rollup did not introduce this. v8.1.0 behaved the same way, and a dependency bump is outside the scope for changing tool-pinning policy.
**Effect if left as is:** Every CI run downloads the newest uv release. The `docker` and `dependencies` jobs run `uv export --locked … --format requirements-txt` and compare the output against the image's `pip freeze`. A uv release that changes export output or lockfile handling could turn CI red with no change on our side, and the uv binary is the one unpinned tool in a pipeline that otherwise pins Trivy by checksum and pip-audit by version. setup-uv v10 adds `version: "latest-known"`, which only installs uv releases whose checksums the action knows. That would partly close the gap.
**Needs:** A ruling from the developer: pin uv (`version:` or `required-version`), adopt `latest-known`, or accept as is.
