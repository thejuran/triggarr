# Phase 85.1 Plan 01: Inspection-Only Checker Mode Summary

**Caller-declared `--review-mode inspection-only` grading mode added to `tests/codex_report_status.py`, so a review of an untrusted head that runs no commands and reproduces nothing can be graded complete on its own terms, while the trusted-mode hollow-report guard stays byte-for-byte unchanged.**

## Accomplishments
- `assess_report()` accepts a caller-declared `review_mode` (`"trusted"` default, `"inspection-only"`), validated against a new `REVIEW_MODES` constant; an invalid value raises `ValueError` naming `REVIEW_MODES` rather than yielding a report verdict
- Inspection-only mode skips the D-18 hollow-report command guard and instead rejects a non-empty `commands_run` ("inspection-only review must not run commands: commands_run has N entries") and any finding claiming `reproduced: true` ("inspection-only review cannot reproduce findings: `<id>` claims reproduced") -- T-85.1-03 spoofing mitigations
- `--review-mode {trusted,inspection-only}` added to the CLI, defaulting to `trusted`, advertised in `--help` so the runner (Plan 85.1-05) can detect a trusted-main checker that predates the mode (B13 support check)
- `Assessment` gained a `review_mode` field (default `"trusted"`, last positional slot) emitted as the final key of the assessment JSON

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Early-return Assessment() constructions silently defaulted review_mode to "trusted"**
- **Found during:** Task 2 (adding the `review_mode` field to `Assessment`)
- **Issue:** The plan's Task 2 instructions covered the final return and the dataclass default, but seven early-return paths (missing report, unreadable report, duplicate-key/nested-duplicate-key JSON, over-long-integer JSON, non-dict report) construct `Assessment` positionally before any mode-specific logic runs. Left alone, these would always report `"review_mode": "trusted"` in the output JSON even when the caller declared `--review-mode inspection-only`, misreporting which rules were requested for that run.
- **Fix:** Added `review_mode` as the 7th positional argument to all seven early-return `Assessment(...)` calls, so every output path -- not just the one that runs the full rule set -- reports the mode the caller actually declared.
- **Cost if wrong:** Low. These are edge cases (malformed/unreadable input) where the mode had no behavioral effect anyway; the only consequence of leaving it unfixed would be a misleading `review_mode` field in the JSON for those specific failure modes. No downstream consumer reads this field yet in this plan.
