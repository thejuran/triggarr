### What is and is not enforced

**Enforced:** no host home, repository, host `~/.codex`, SSH agent, Docker
socket, GitHub or cloud credential is ever mounted or forwarded into the
container; the container runs non-root; the root filesystem is read-only;
all Linux capabilities are dropped; `no-new-privileges` is set; the output
schema mounted into the container is read-only and hash-checked; the only
input Codex receives is the inert text on stdin; Codex's own tool features
(`DISABLED_FEATURES` above) are disabled as defense in depth; every
container this run creates is confirmed removed (`docker rm -f` followed by
a `docker ps -a` absence check, never trusting `rm`'s own exit code) before
its output is ever read.

**Not enforced:** network egress. The review container uses Docker's normal
bridge network with no published ports — egress is **not restricted to the model endpoint** and the container is not network-isolated (D-04). The
owner's Codex sign-in is copied into the container by necessity (D-06/D-07):
it is the only secret inside, deleted after every run, never copied back,
and the host's `~/.codex` itself is never mounted — but if the container
boundary and Codex's own tool-disabling both failed at once, the owner's
main Codex session inside the container could still reach the open network.
The owner accepted this residual risk knowingly (D-07, 2026-10-28).

### Why it is outside the plan sequence (PC-04)

D-02 requires main's grader, which exists only after the phase PR merges,
and CLAUDE.md requires the phase-execution review to fire once after all
plans complete. Putting the live run in a plan would place a plan after the
phase's review and push. So the plans end with 85.1-10, and this run is the
phase's verification gate.

### Preconditions

1. The owner has merged the Phase 85.1 PR (Claude never merges or approves;
   D-01). After a fresh `git fetch --no-tags origin +refs/heads/main:refs/remotes/origin/main`,
   `git merge-base --is-ancestor <merge SHA> origin/main` succeeds.
2. Planning is updated on a new local branch from the freshly fetched
   `origin/main` (never on `main`). STATE `status`: "Phase 85.1 in main via
   PR #<n>; live verification of the inspection-only review on PR #<N>
   pending (verifying)". STATE `stopped_at`, Current Position and the
   ROADMAP Phase 85.1 line say "merged, awaiting live verification (D-03)",
   with the checkbox unchecked and `last_updated` refreshed. D-03's wording
   goes in the prose fields. The `status` field avoids the words merged,
   await, complete and done, because `docs/PLANNING-FORMAT.md` reads
   `merged`/`complete`/`done` there as finished and `Awaiting` as between
   milestones. The phase is never shown as complete at this point.
3. The host sign-in's `last_refresh` is within 7 days (D-11 amendment);
   otherwise the run stops INCOMPLETE before any copy and the owner runs
   `codex login` (or uses Codex on the host) first.

### Procedure

1. **Proof PR (D-09):** `gh pr view 47 --repo thejuran/triggarr --json state,author,headRefOid,baseRefOid`.
   Use it if it is OPEN and
   `gh api repos/thejuran/triggarr/commits/<headRefOid>/check-runs --paginate --slurp`
   shows the latest "CI ready" completed with success. Otherwise take the
   newest PR from
   `gh pr list --repo thejuran/triggarr --author app/dependabot --state open --json number,headRefOid,createdAt`
   that has that CI evidence. If none qualifies, stop and tell the owner. A
   closed, merged or historical head is never used.
2. **Base:** `git fetch --no-tags origin pull/<N>/head`, then
   `git merge-base <baseRefOid> <headRefOid>`.
3. **Detached worktree:** Create a detached worktree of fresh `origin/main`
   with `git worktree add --detach <tmp>/main origin/main` and run
   everything below from it. The runner itself refuses unless its HEAD
   equals the freshly fetched `origin/main` (D-02). There is no bootstrap
   exception.
4. **Image:** Confirm the review image exists
   (`docker image inspect triggarr-codex-review:0.153.4`), or build it with
   `REVIEW_IMAGE_BUILD_ARGV`. Then run
   `uv run python tests/codex_review_run.py --verify-boundary`.
5. **Run:**
   `uv run python tests/codex_review_run.py --untrusted --pr-url https://github.com/thejuran/triggarr/pull/<N> --head <headRefOid> --base <merge-base> --label untrusted-e2e --attempt 1 --scope "Phase 85.1 post-merge live end-to-end inspection-only review (D-03)" --phase-dir .planning/phases/85.1-isolated-codex-review-for-untrusted-prs`.
6. **Gate + readiness:** Run
   `uv run python tests/codex_review_run.py --completion-gate .planning/phases/85.1-isolated-codex-review-for-untrusted-prs/codex/<head12>-untrusted-e2e-a1`,
   then
   `node .github/scripts/acceptance-readiness.cjs --pr <N> --codex-out <same prefix>`
   and record its Codex line.
7. **Container check:** Run
   `docker ps -a --filter ancestor=triggarr-codex-review:0.153.4 --format '{{.ID}}'`.
   It must print nothing.
8. **Authenticated host check (D-08; RESEARCH Open Question 1, RESOLVED):**
   in an empty temp dir, run
   `codex exec --ephemeral --skip-git-repo-check --sandbox read-only -C <dir> "Reply with the single word OK."`
   with no PR content. It must succeed. `codex login status` may be recorded
   too, but it is not proof.
9. **Cleanup:** Copy the attempt's raw outputs into this branch's phase
   `codex/` dir, run the contract's secret scan on them before committing,
   and remove the worktree.

### Pass criteria (D-03, all required)

- `--completion-gate` exits 0 for the selected attempt. That means boundary
  verdict `verified`, `.status.json` complete, `.base-status.json` complete
  when a cross-grade is needed, and grader provenance from `origin/main`.
- The readiness Codex line is ok without a fallback.
- No review container survived.
- The authenticated host call succeeds.

### Escalation

- Any other outcome is recorded as "## Post-merge live run (D-02, D-03):
  INCOMPLETE — <reasons>". The owner is told in plain terms.
- STATE `status` becomes "Phase 85.1 blocked -- post-merge live review
  INCOMPLETE (<short reason>); follow-up PR needed". The ROADMAP checkbox
  stays unchecked, and the fix goes in a follow-up PR. Nothing is reported
  clean.
- A transient failure (for example a Codex service error) gets attempt 2
  under the contract's one-automatic-retry rule only with the owner's
  consent.
- Boundary, provenance, credential-refresh, cleanup or tool-use failures are
  never retried. They are escalated.
- If the host call fails after the run, the owner re-logs in with
  `codex login`, and the run counts as INCOMPLETE (D-08/D-11).
