## Post-merge live verification hand-off (phase verification gate, not a plan task)

Why it is outside the plan sequence (PC-04): D-02 requires main's grader, which exists only after the phase PR merges, and CLAUDE.md requires the phase-execution review to fire once after all plans complete. Putting the live run in a plan would place a plan after the phase's review and push. So the plans end here, and this run is the phase's verification gate (85.1-VALIDATION.md, Manual-Only Verifications). It is executed by the verifier or `/bm:verify-work 85.1` after the owner merges. Task 1 copies these steps into the evidence file.

Preconditions:
1. The owner has merged the Phase 85.1 PR (Claude never merges or approves; D-01). After a fresh `git fetch --no-tags origin +refs/heads/main:refs/remotes/origin/main`, `git merge-base --is-ancestor <merge SHA> origin/main` succeeds.
2. Planning is updated on a new local branch from the freshly fetched origin/main (never on main). STATE `status`: "Phase 85.1 in main via PR #<n>; live verification of the inspection-only review on PR #<N> pending (verifying)". STATE `stopped_at`, Current Position and the ROADMAP Phase 85.1 line say "merged, awaiting live verification (D-03)", with the checkbox unchecked and last_updated refreshed. D-03's wording goes in the prose fields. The `status` field avoids the words merged, await, complete and done, because docs/PLANNING-FORMAT.md reads `merged`/`complete`/`done` there as finished and `Awaiting` as between milestones. The phase is never shown as complete at this point.
3. The host sign-in's last_refresh is within 7 days (D-11 amendment); otherwise the run stops INCOMPLETE before any copy and the owner runs `codex login` (or uses Codex on the host) first.

Procedure:
1. Proof PR (D-09): `gh pr view 47 --repo thejuran/triggarr --json state,author,headRefOid,baseRefOid`. Use it if it is OPEN and `gh api repos/thejuran/triggarr/commits/<headRefOid>/check-runs --paginate --slurp` shows the latest "CI ready" completed with success. Otherwise take the newest PR from `gh pr list --repo thejuran/triggarr --author app/dependabot --state open --json number,headRefOid,createdAt` that has that CI evidence. If none qualifies, stop and tell the owner. A closed, merged or historical head is never used.
2. Base: `git fetch --no-tags origin pull/<N>/head`, then `git merge-base <baseRefOid> <headRefOid>`.
3. Create a detached worktree of fresh origin/main with `git worktree add --detach <tmp>/main origin/main` and run everything below from it. The runner itself refuses unless its HEAD equals the freshly fetched origin/main (D-02). There is no bootstrap exception.
4. Confirm the review image exists (`docker image inspect triggarr-codex-review:0.153.4`), or build it with REVIEW_IMAGE_BUILD_ARGV. Then run `uv run python tests/codex_review_run.py --verify-boundary`.
5. Run `uv run python tests/codex_review_run.py --untrusted --pr-url https://github.com/thejuran/triggarr/pull/<N> --head <headRefOid> --base <merge-base> --label untrusted-e2e --attempt 1 --scope "Phase 85.1 post-merge live end-to-end inspection-only review (D-03)" --phase-dir .planning/phases/85.1-isolated-codex-review-for-untrusted-prs`.
6. Run `uv run python tests/codex_review_run.py --completion-gate .planning/phases/85.1-isolated-codex-review-for-untrusted-prs/codex/<head12>-untrusted-e2e-a1`, then `node .github/scripts/acceptance-readiness.cjs --pr <N> --codex-out <same prefix>` and record its Codex line.

Authenticated host check (D-08; RESEARCH Open Question 1, RESOLVED): in an empty temp dir, run `codex exec --ephemeral --skip-git-repo-check --sandbox read-only -C <dir> "Reply with the single word OK."` with no PR content. - No review container survived.
- The authenticated host call succeeds.

- If the host call fails after the run, the owner re-logs in with `codex login`, and the run counts as INCOMPLETE (D-08/D-11).

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-85.1-43 | Information disclosure | Credential or home paths in committed evidence | mitigate | Markers and names only; verify gate greps for $HOME; never print credential contents |
| T-85.1-44 | Repudiation | Probe silence presented as proof | mitigate | Verdict from deterministic checks only; probe labelled "supplementary, not proof" |
| T-85.1-45 | Elevation of privilege | Relaxing checks to get a green verdict | mitigate | Action forbids changing flags, mounts, sandbox mode or checks; failure goes to the owner decision |
| T-85.1-46 | Denial of service | Live run refreshing and invalidating the host login | mitigate | 7-day freshness preflight (owner `codex login` when older), post-run hash compare, authenticated minimal host Codex call recorded (login status alone is not proof) |
| T-85.1-47 | Elevation of privilege | Running the live review with the branch's grader before merge | mitigate | The post-merge run is a verification gate after the owner's merge, from a detached fresh origin/main worktree; the runner refuses unless HEAD equals origin/main (D-02) |
| T-85.1-48 | Repudiation | Reporting an INCOMPLETE live run as complete, or silent retries | mitigate | Completion only via `--completion-gate` exit 0 plus the host call; retries need owner consent; STATE says blocked otherwise |
| T-85.1-49 | Spoofing | Using a closed or historical head as proof | mitigate | Proof PR must be OPEN with CI ready success for its current head (D-09) |
