## Info

### IN-01: For an unknown change set, the Codex item tells the operator to do something that will not unblock the PR

**File:** `.github/scripts/acceptance-readiness.cjs:140-147`
**Issue:**
- **What the item says:** when `ciIndependenceRequired` holds, the blocked Codex detail always says "rerun the inspection-only review, which stops with the CI-independence reason, then record the owner-approved fallback".
- **When that is wrong:** `ciIndependenceRequired` is also true when readiness's own `git diff ... -- .github` failed (`ciDefinitionsChanged === null`). In that case the runner's own diff, over the same `BASE..HEAD`, may succeed and find no change. A rerun then produces another COMPLETE record and never the stop, so the advice sends the operator into a loop.
- **How likely it is:** low. `runCli` has already run `git merge-base` and the audited-input diff over the same range, and returns exit 1 if either fails. So the `.github` diff failing on its own takes a transient error or the output buffer limit.
- **Why it still matters:** it is still a wrong instruction in the one case the IN-01 fix was meant to make honest.
**Fix:** Branch the detail on `ciDefinitionsChanged`. For `true`, keep the current text. Otherwise say: "whether .github/ changed could not be determined (see CI ready); fix the local checkout or fetch and rerun the readiness check, or record the owner-approved fallback". This needs `ciDefinitionsChanged` passed into `codexStatusFor`, or a reason string instead of a boolean.

### IN-02: `codex-fallback.cjs validate` re-verification reads the PR's author but does not bind the PR to `--head` or `--pr-author`

**File:** `.github/scripts/codex-fallback.cjs:636-660`, `715-717`
**Issue:**
- **What it reads:** `ciIndependenceRequiredFor` asks GitHub only for `author,isCrossRepository`.
- **What it does not check:**
  - that PR `#<pr>`'s `headRefOid` is `--head`;
  - that GitHub's author login equals the operator-supplied `--pr-author`, which `validateFallback` still uses.
- **What a typo can do:** if the operator types the wrong PR number, the exception is decided by a different PR's author and fork status, while the `git diff` runs on the intended head.
  - Example: a Dependabot head's stop record validated with a fork PR's number would get the attempt-1 exception.
  - The record's own `pr` field must also match, so the same typo has to appear in two places.
- **Where the diff runs:** `git diff` uses the process's current directory, not the repository root. Run from anywhere else, it fails and is treated as a change, which grants the exception for a covered PR.
- **What limits the impact:**
  - The attempt-number rule is the only thing affected.
  - The runner never writes a CI-independence stop for an uncovered head, so this needs a stale or hand-edited stop record as well as the typo.
  - The readiness check, which is the real gate, reads `headRefOid` from `gh` itself and is unaffected.
**Fix:** Request `author,isCrossRepository,headRefOid`. Refuse the exception, and log why, when `headRefOid !== head` or `author.login !== prAuthor`. Pass `{cwd: path.resolve(__dirname, '..', '..')}` to the git call. Add two runCli tests, one per mismatch.

### IN-03: The `.github` pathspec and the one-line error formatter are now copied three ways, with no drift pin

**File:** `.github/scripts/codex-fallback.cjs:12-15`, `625-627`; `.github/scripts/acceptance-readiness.cjs:50`, `631-632`; `tests/codex_review_run.py:1110`
**Issue:**
- **The pathspec:** `CI_DEFINITION_PATHSPEC = '.github'` is defined separately in both JS files and as `CI_DEFINITION_PATHSPECS` in Python. No test compares them; the CLI tests hardcode `'.github'` in their exec keys.
- **The formatter:** `oneLine()` in `codex-fallback.cjs` repeats the inline expression in `acceptance-readiness.cjs:631-632`.
- **Why it matters:** if one copy is widened (for example, adding another CI-defining path), the other two would quietly diverge. The rule's whole point is that the runner, readiness and the validator agree.
**Fix:**
- Export `CI_DEFINITION_PATHSPEC` from `acceptance-readiness.cjs`, which `codex-fallback.cjs` already requires lazily, and import it rather than redefining it.
- Export and reuse `oneLine`.
- Add a drift assertion next to the existing `CI_NOT_INDEPENDENT_REASON` pin, comparing the JS constant with the Python tuple.
