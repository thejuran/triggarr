# Phase 85.1 Plan 06: Inspection-Only Orchestration, Boundary Gate and Launch Seam Summary

**`--untrusted` now runs a fail-closed, fully orchestrated inspection-only review (D-07) instead of refusing outright: it reserves outputs, records CI evidence and trusted-main grader provenance, enforces a mandatory isolation-boundary gate before the single Codex launch seam, audits the event stream, and grades with `--review-mode inspection-only` (cross-graded from `origin/main` when the diff touched the checker itself) -- every run still ends INCOMPLETE (exit 3) until Plans 85.1-07/08 fill in the real container checks and launch.**

## Accomplishments
- `inspection_codex_argv()` builds the read-only, ephemeral inner `codex exec` command with all 22 required features disabled via `--disable` (confirmed present in `codex features list` on codex-cli 0.153.4); never contains `--add-dir`, `workspace-write`, `danger-full-access` or any `--dangerously-*` flag
- `audit_event_types()` fails closed on any item type outside `{agent_message, reasoning}` or event type outside the six allowed top-level types, on a missing event-stream file, and raises on an unparseable line
- `verify_isolation_boundary()` is the mandatory precondition seam (currently always `"unverified"`, issuing no command) and `run_untrusted_codex()` is the only seam that may reach Codex for an untrusted head (currently always refuses) -- both fixed, tested contracts Plans 85.1-07/08 fill in behind
- `execute()`/`_execute_untrusted()`/`_execute_inspection()` wire the full inspection-only pipeline end to end: pre-reservation gathering (PR/CI preconditions, inert input, prompt) never writes anything on failure; the existing-output check and reservation follow the trusted path's exact shape; `.meta.json`, `.ci-evidence.json`, `.grader-provenance.json` and `.boundary.json` are each written with `_write_json_atomic`; grading uses `checker_argv(..., review_mode="inspection-only")` against the head re-read via a second `gh pr view`; a diff that changed the checker/schema/prompt/runner also cross-grades with the trusted-main checker into `.base-status.json`
- The interim refusal machinery (`UNTRUSTED_REFUSAL`, `UNTRUSTED_STATUS_REASON`, `untrusted_refused_meta`, `_untrusted_main`) is removed; the trusted path is otherwise unchanged
- `dry_run_untrusted()` previews the inspection-only prompt (with `INPUT` shown as `<inert input: built at run time>`), the PR/CI precondition commands, the `origin/main` fetch and ancestor check, and the inner Codex argv, without running or writing anything
