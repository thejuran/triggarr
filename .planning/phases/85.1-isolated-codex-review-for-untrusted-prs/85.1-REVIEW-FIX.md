### CR-01 / Codex F001: completion_gate() passes on non-object JSON

**Files modified:** `tests/codex_review_run.py`
**Applied fix:** `completion_gate._read()` appends "`<prefix><suffix>` is not a JSON object" when a record parses but is not an object, so no required check is skipped.

### WR-02 / Codex a2 F002: inspection path never re-checks the grader

**Files modified:** `tests/codex_review_run.py`, `docs/codex-adversarial-review-contract.md`
**Applied fix:** new `_reverify_trusted_grader()` runs after the Codex run and before the checker. It re-runs `establish_trusted_main()`, which does a fresh origin/main fetch and checks HEAD == origin/main, clean audited inputs and base-on-main. It requires the same `main_sha`/`harness_head`/`grader_ref` as before the run, then re-audits the input hashes against `.meta.json`. On any drift the run rewrites `.grader-provenance.json` as `established: false` with the reason and records INCOMPLETE (exit 3), and the checker never runs.

### Codex a1 F002: event audit only checked item.completed

**Files modified:** `tests/codex_review_run.py`
**Applied fix:** `audit_event_types()` checks `item.type` on every `item.*` event (started, updated and completed). It reports each item id once.

### WR-01: post-reservation failures exited 2 with no status

**Files modified:** `tests/codex_review_run.py`, `tests/test_codex_review_container.py`
**Applied fix:** `materialize_grader` and `audit_event_types` failures, including a truncated last `.jsonl` line, go through `_inspection_incomplete`. `_execute_untrusted` turns any other post-reservation `RunnerError` into an incomplete stub, or keeps the status the failing step already wrote, and returns 3. The existing `test_cleanup_escalation_launch_prep_failure_execute_inspection` was updated from expecting a raise to expecting exit 3, with the same status assertions.

### WR-03: CI ready could come from a head-defined job

**Files modified:** `tests/codex_review_run.py`, `docs/codex-adversarial-review-contract.md`
**Applied fix:** `ci_evidence()` counts only `CI ready` check runs whose `app.slug` is `github-actions` (the app behind `ci.yml`'s `ci-ready` job) and that carry a check suite. If more than one check suite (workflow) posted one for the head, the evidence is refused. Within the single workflow the latest result still wins, so re-runs keep working. Recorded `.ci-evidence.json` fields are unchanged.

### WR-04: narrowed host-exposure check missed argv forms

**Files modified:** `tests/codex_review_run.py`
**Applied fix:** `host_exposure_problems()` now applies an exact allowlist to both argvs:
- The argv must start with `docker create`, followed by exactly `--entrypoint /bin/sh` for the canary and never an entrypoint override for the review container.
- It must use `REVIEW_IMAGE_REF`.
- The option section may use only allowlisted options with separate value tokens. Any other option is a reason that names only the option, never its value. The option section must also equal `_container_options(*per_run_dirs)` exactly.
- Mount sources may use `src=` or `source=` and must be one of the per-run directories.

The absolute-token protected-path scan still runs on the rest of the argv. The duplicated `_protected_marker` closure was replaced by `_protected_path_marker` (which also resolves IN-03 as a side effect).

### WR-05: JS readiness ignored provenance and prefix attempt

**Files modified:** `.github/scripts/codex-fallback.cjs`, `.github/scripts/acceptance-readiness.cjs`, `.github/scripts/codex-fallback.test.cjs`, `.github/scripts/acceptance-readiness.test.cjs`, `.github/scripts/codex-completeness-parity.test.cjs` (RED), `docs/review-checkpoint-record.md`
**Applied fix:** `inspectionOnlyCompleteness()` now takes `provenance` and `out` and applies the Python gate's rules:
- The provenance must be established, with `base_on_main === true` and `grader_source === "trusted-origin-main"`.
- `meta.head` must start with the prefix's head12, and `meta.attempt` must equal the prefix's `-aN`.

`codexStatusFromOutput` and `runCli` read `<OUT>.grader-provenance.json`. The parity test sends every inspection-only row through the real Python `completion_gate()` (via `uv run --frozen python`) and asserts that both acceptors agree. Existing JS fixtures gained a valid provenance, and the `runCli` fixture's meta attempt now matches its `-a2` prefix.

### WR-06: unredacted host paths in committed evidence

### WR-07: open-PR check failed open on unknown state

**Files modified:** `tests/codex_review_run.py`
**Applied fix:** `inspect_untrusted_pr()` requires `state == "OPEN"`. Anything else is refused, and an unrecognized value is not echoed.

### WR-08: head file names passed as pathspecs

**Files modified:** `tests/codex_review_run.py`, `tests/test_codex_review_inspection.py`
**Applied fix:** `_ls_tree_entry()` runs `git --literal-pathspecs ...`. This was verified against real git: a file named `:(glob)b` used to abort, and `:(top)x` was looked up as `x`. Only this call gets the flag, because the fixed `EXCLUDE_PATHSPECS` used elsewhere depend on pathspec magic. The scripted build-input fixture now expects the new argv.

### WR-09: image trusted by tag and label only

**Files modified:** `tests/codex_review_run.py`, `docs/codex-adversarial-review-contract.md`
**Applied fix:** the build labels the image with `org.triggarr.codex-review.dockerfile-sha256=<sha256 of docker/codex-review/Dockerfile>` (new `review_image_build_argv()`, and `REVIEW_IMAGE_BUILD_ARGV` shows the shell form). `verify_isolation_boundary()` refuses an image whose label is missing or differs from the checkout's Dockerfile. It records `image_id` and `dockerfile_sha256` in the boundary, and, as before, requires the created review container's `Image` to equal that resolved ID. The docstring was corrected.

### WR-10: no Dependabot coverage for the review image
