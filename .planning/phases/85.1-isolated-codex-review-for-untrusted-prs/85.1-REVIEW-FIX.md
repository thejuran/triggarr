### Codex 0aeeeda F001: inspection limits were enforced only after unbounded reads

**Files modified:** `tests/codex_review_run.py`
**Applied fix:**
- `run_command` takes a `max_output_bytes` option. `_run_bounded_output` streams stdout in chunks, stops reading just past the bound and kills the command, so the host never holds more than the bound plus one byte.
- `_git_bounded()` replaces `_git_bytes()`. It returns None when output exceeds the bound, and checks the size before the exit code, because a command stopped early exits non-zero.
- `build_inspection_input()` keeps a running byte count against `MAX_INSPECTION_INPUT_BYTES`:
  - Both diffs are read with the remaining budget as their bound.
  - The changed-path lists are read with the whole budget as their bound.
  - Each blob's size is read with `git cat-file -s` first. A blob over `PER_FILE_CONTENT_LIMIT` is omitted without being fetched, and a blob that would not fit the remaining budget ends extraction.
  - The first read that would exceed the budget stops extraction and returns empty text, with `oversize: true`.
- `_execute_untrusted()` no longer renders an oversize input. The reservation records a one-line "prompt not rendered" note, and `_execute_inspection` records INCOMPLETE before anything else runs.
- The output text is unchanged for inputs within the limits (the existing byte-count and content tests still pass).
