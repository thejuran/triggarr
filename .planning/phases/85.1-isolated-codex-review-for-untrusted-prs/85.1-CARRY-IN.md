# Phase 85.1 carry-in: isolated Codex review for untrusted PRs

Split out of Phase 85 planning on 2026-10-27 by owner decision ("Split into Phase 85.1"). Input for `/bm:discuss-phase 85.1`, not a plan.

## Why it was split

Phase 85 CONTEXT D-07 says bot PRs (Dependabot) get the same paired BM + Codex review as any code PR. Running Codex on an untrusted head safely needs a new security boundary. During Phase 85 planning the plan checker found new blockers in that boundary design in every round (iterations 1-3 plus one extra owner-authorized round). The rest of Phase 85 passed. The owner chose to build this boundary hands-on in its own small phase instead of designing it further on paper.

## Interim rule until 85.1 ships (owner decision 2026-10-27)

Bot and fork PRs get CI plus a per-PR owner-approved fallback review recorded under the D-16 fallback definition (Phase 85). Untrusted-mode Codex runs stay refused and are recorded INCOMPLETE, never clean. D-07 remains the goal.

## Starting material

- `DRAFT-85-20-inspection-only-review.md` and `DRAFT-85-21-isolation-boundary.md`: the last Phase 85 drafts. They cover the inert-input packet, the trusted-main grader with an ancestor check, the disposable container, the deterministic config check and the completion gate. They are reference only and must be re-planned.
- Open findings from the last check round, which the design must address:
  - **B15:** the host reads `/out/last.json` from a container-writable directory, so a symlink or FIFO can import host secrets or hang the runner. Stop the container first, then use a no-follow descriptor read, a regular-file check and a size bound. Add symlink and FIFO regressions.
  - **B16:** the environment allowlist rejects Docker's runtime `HOSTNAME` and the shell's `PWD`. Separate the inspected `Config.Env` from runtime additions, without broadly allowing arbitrary names.
  - **B17:** there is no in-container source for the Codex `--output-schema`. Mount the audited schema read-only, check its hash, and add a launch-contract test.
  - **B18:** the completion gate globs every historical attempt, so one failed attempt blocks forever. Bind the gate to the selected attempt's output prefix, and require a base-status file when a cross-grade is needed.
  - Already resolved in the drafts: base-grader provenance is fresh `origin/main` with an ancestor check and a malicious-base regression (B13); isolation is deterministic, not behavioral (B04-R3); completion requires a COMPLETE live review (B14).
- Main's checker learns the new inspection-only flag only after Phase 85 merges. Plan the bootstrap accordingly.
