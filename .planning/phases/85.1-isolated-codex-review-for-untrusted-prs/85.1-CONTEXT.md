# Phase 85.1: Isolated Codex Review for Untrusted PRs - Context

**Gathered:** 2026-10-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver Phase 85 D-07's normal paired review for bot (Dependabot) and fork PRs. Codex reviews an untrusted head through an enforced isolation boundary: the input is inert text, the grader comes from trusted `origin/main`, and Codex runs in a disposable container whose configuration is checked deterministically. The head's code is never checked out, written to disk or executed, and never runs with access to host secrets.

Out of scope: restricting container network egress (see Deferred), any new review lane for bot PRs (D-07: they are classified by content like any PR), changes to the trusted-mode runner beyond what the shared code needs, and any override flag.

</domain>

<decisions>
## Implementation Decisions

### Live end-to-end test timing (bootstrap)
- **D-01:** One PR for the phase, per the one-PR-per-phase rule. Until it merges, main keeps refusing `--untrusted` and recording INCOMPLETE, so no unsafe window opens.
- **D-02:** The required live end-to-end review (success criterion 3) runs **after merge**, using main's grader, which by then knows the inspection-only mode. The grader-from-main rule is never relaxed and there is no bootstrap exception run with the branch's grader.
- **D-03:** Phase 85.1 is not marked complete until that post-merge live run returns COMPLETE (boundary verdict "verified", `.status.json` complete, and `.base-status.json` complete when a cross-grade is needed). Until then, STATE and ROADMAP show the phase as merged and awaiting live verification, not complete. If the run fails, it stays fail-closed (INCOMPLETE), the owner is told, and the fix goes in a follow-up PR. Never report it clean. The plan must record pre-merge evidence (deterministic tests, a local `--verify-boundary` against the built image, mutation and regression tests) separately from the post-merge live run.

### Network egress
- **D-04:** The review container uses Docker's normal network with no published ports. Egress is **not** restricted to the model endpoint. That limitation must be stated plainly in the contract docs and the boundary evidence. Never imply the container is network-isolated.
- **D-05:** Add a backlog item for "restrict review-container egress to the OpenAI endpoint" (`.planning/backlog/MAINTENANCE.md`). It is not built in this phase.

### Codex credential
- **D-06:** The container receives a **copy of the owner's existing Codex sign-in file**. It is the only secret inside, the copy is deleted after every run, and it is never copied back to the host. The host's `~/.codex` is never mounted. No dedicated API key.
- **D-07:** Record the accepted residual risk plainly: the main Codex session is in the container and egress is open (D-04). If the container boundary **and** Codex's tool-disabling both failed, the owner's main session could leak. The owner chose this knowingly (2026-10-28).
- **D-08:** Research must establish whether Codex refreshes or rotates its sign-in token during a run, in a way that would invalidate the host's copy. If it does, the design must detect it and stop (INCOMPLETE, with a clear owner message), not copy the refreshed credential back, which would break D-06. Showing that the host login still works after a run is part of the live evidence.

### Proof PR
- **D-09:** Dependabot **PR #47** (pytest-asyncio 1.4.0 → 1.4.1, dev-only, opened 2026-10-28) stays open, without the interim fallback, and is the live end-to-end test once 85.1 merges. If it goes stale, gets superseded or is closed first, use whatever Dependabot PR is open at that point. A closed or historical head is not acceptable as the proof.
- **D-10:** Any other bot or fork PR that arrives before 85.1 ships follows the interim rule (CI plus a per-PR owner-approved fallback under Phase 85 D-16).

### Carried forward (locked, not re-discussed)
- Missing, failed, skipped, stale or wrong-commit evidence is never clean. Incomplete outcomes block and are escalated. There is no override flag and no "either verdict accepted" path (Phase 85 / drafts B14).
- The base grader comes only from a fresh `origin/main` fetch, with an ancestor check. A fork-controlled base is rejected before any of its Python runs (B13).
- Isolation is proven deterministically (`docker inspect` of the created container against the expected config). Behavioral probes are supplementary only (B04-R3).
- The four open plan-checker findings are **mandatory fixes** in the design: B15 (stop the container, then a no-follow, regular-file, size-bounded read of `/out/last.json`, plus symlink and FIFO regressions); B16 (separate inspected `Config.Env` from Docker or shell runtime additions such as `HOSTNAME`/`PWD`, without a broad allowlist); B17 (mount the audited output schema read-only, check its hash, and add a launch-contract test); B18 (bind the completion gate to the selected attempt's output prefix, and require a base-status file when a cross-grade is needed).

- Test structure, file layout and naming, within the existing `tests/codex_review_run.py` / `tests/codex_report_status.py` patterns.

## Existing Code Insights

### Reusable Assets
- `tests/codex_review_run.py`: the runner. `--untrusted` currently goes through `_untrusted_main()` (≈L1349), which writes an `untrusted-refused` meta and an INCOMPLETE status (`untrusted_refused_meta()` ≈L889). The trusted path's verified-origin check (≈L527) already rejects bot authors with "use --untrusted". This is the seam to replace with the inspection-only path.
- `tests/codex_report_status.py`: the grader. It has no `--review-mode` yet, so the inspection-only mode is new. It already has the self-declared-INCOMPLETE detection and the hollow-report command guard (the guard must be skipped only in inspection-only mode).
- The trusted-mode cross-grade from main (Phase 85-13) is the pattern for base-grader provenance.

### Established Patterns
- Fail-closed result files: `<OUT>.meta.json` / `<OUT>.status.json`, with exit 3 for incomplete.
- TDD with golden argv tests and mutation tests. The tests live beside the runner in `tests/`.
- Review-machinery drift guard (85-16): changes to these files are sensitive and in Codex scope.

### Integration Points
- Docker Desktop 29.4.3 runs locally on the owner's Mac. Codex runs locally, not in CI.
- GitHub `CI ready` check run for the exact head, read with `--paginate --slurp`.
- `docker/` does not exist yet. The review image (`docker/codex-review/Dockerfile`) is new.
