# Phase 85.1 Plan 05: Inspection Input, Preconditions and Trusted-Main Provenance Summary

**New functions in `tests/codex_review_run.py` build the untrusted-head review's inert input purely from git objects (diff/ls-tree/cat-file, never a checkout), confirm GitHub CI evidence and PR state for the exact head, render the inspection-only prompt, and establish that the grader is a freshly fetched `origin/main` before any grader code runs -- no orchestration yet, that is Plan 85.1-06.**

## Accomplishments
- `inspect_untrusted_pr()` verifies an untrusted PR is open, matches `--head` via both `gh pr view` and a fresh `pull/<N>/head` fetch, and that `--base` is the merge-base of the PR's base and head -- bot authors and cross-repository forks are accepted by design
- `flatten_pages()`/`ci_evidence()` fail closed on malformed or missing `--paginate --slurp` pages and require the highest-id `CI ready` check run for exactly the reviewed head to have completed successfully
- `build_inspection_input()` builds the full in-scope diff, the phase-plan diff, and a per-path "Changed files at head" section entirely from `git diff`/`ls-tree`/`cat-file`, through `GIT_SAFE_PREFIX` and `--no-textconv --no-ext-diff --no-color`; oversize, binary, symlink, submodule and deleted paths are each noted and omitted, and the untrusted head's content never touches disk
- `new_input_fence()`/`render_inspection_prompt()` generate a random `TRIGGARR-INERT-<hex>` fence (regenerated on collision) and render the contract's inspection-only prompt with all seven placeholders substituted in one pass
- `establish_trusted_main()` fetches `origin/main` fresh, requires the harness checkout's own HEAD to equal that SHA (D-02, no bootstrap exception), requires clean audited inputs, and requires `--base` to be an ancestor of main (B13) before returning grader provenance -- it never reads or runs anything from `--base`
- `trusted_main_grader_supports_mode()` checks a materialized checker's `--help` output for `--review-mode`/`inspection-only` support, reporting `False` rather than raising for an older checker
- Generalized `load_template()`/`render_prompt()` into heading- and placeholder-parameterized `load_template(heading=)`/`render_template()`, with `render_prompt()`'s own behavior and error messages unchanged (the existing `tests/test_codex_review_run.py` suite passes unmodified)

## Decisions Made
- `inspect_untrusted_pr()` deliberately does not reuse `verify_trust()`'s bot/fork rejection -- the two functions clear opposite head types (trusted-local-execution vs. untrusted-inspection-only), so duplicating the GitHub-state checks with different acceptance rules was clearer than threading a mode flag through the existing trusted-path function.
- `ci_evidence()` returns a dict with both the full per-head `check_runs` list and the selected `ci_ready` entry (rather than only the latter), so a future caller (Plan 85.1-06's `.ci-evidence.json`) can record the fuller evidence set without a second GitHub call.
- Kept `_require_base_on_main()` (the trusted path's own ancestor check) completely untouched; `establish_trusted_main()` is a separate, independent rule for the untrusted path, per the plan's explicit instruction not to conflate the two.
