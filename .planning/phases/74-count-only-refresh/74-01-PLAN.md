<objective>
Extract the shared fetch → raw-count → health → tag → filter → eligible/searchable-count prefix out of each `run_*_cycle` in `triggarr/search/engine.py` into three per-app helpers — `refresh_radarr_counts`, `refresh_sonarr_counts`, `refresh_lidarr_counts` — and refactor the three cycle functions to call their helper, then continue into the existing slice + search + cursor-advance + `last_run`/`last_success` block unchanged.

This is the engine foundation for the whole phase. The structural cursor guarantee (CNT-02) is established here: `slice_batch` and every cursor/`last_run`/`last_success` write stay EXCLUSIVELY in the cycle function, so any caller of the helper alone (the Plan 02 endpoint) cannot advance the cursor or stamp run times.

Purpose: Make accurate counts available without a search, while keeping the scheduled search path behavior-identical (CNT-01).
Output: Three helpers + three refactored cycles in `engine.py`; new `tests/test_refresh_counts.py` with RED-first engine helper tests; `tests/test_search.py` stays green.
</objective>
