<objective>
Implement the SSRF config-load validation (D-01/D-02) so the README/SECURITY URL-validation claim
becomes accurate by widening the code — NOT by scoping the doc down. This is the GREEN phase: make
the RED tests from plan 01 pass.

Purpose: Close the SSRF gap where a URL set directly in triggarr.toml bypassed validation
(codex HIGH, README:215 / SECURITY.md:39). After this, cloud-metadata and link-local addresses are
blocked at config load too; loopback is permitted there (relaxed variant) for same-host *arr
deployments, while the web settings form stays strict (unchanged).

Note the deliberate hardening tradeoff (do not soften it): config-load URL validation runs on the
`url` field regardless of `enabled`, so on upgrade a configured instance whose URL is genuinely
unsafe (metadata / link-local / non-http / malformed) will now fail at startup EVEN IF that
instance is disabled. Loopback and private-LAN deployments are unaffected; this is intended
hardening, not a regression.

Output: One new function in triggarr/web/validation.py and one new field_validator on
InstanceConfig in triggarr/models/config.py. The plan-01 RED tests turn GREEN; no existing
validation test changes.
