    **Password change (POST /settings/password):**
    - Valid current + matching new/confirm: returns partials/security_password.html with success="Password updated", config updated atomically
    - Wrong current password: returns partial with errors={"current_password": "Current password is incorrect"}
    - Mismatched new/confirm: returns partial with errors={"confirm_password": "Passwords do not match"}
    - Empty new password: returns partial with errors={"new_password": "New password is required"}
    - Config mutation follows lock -> model_copy -> _atomic_toml_write -> chmod -> reload -> _sync_auth_state -> refresh log redaction

    **Auth mode save (POST /settings/security):**
    - method=Basic: writes "Basic" to config, redirects 303 to /settings
    - method=External: writes "External" to config, redirects 303 to /settings
    - method=Forms: writes "Forms" to config, redirects 303 to /settings
    - method=Disabled: rejected -- returns 303 redirect without config change (D-13: no Disabled in UI)
    - method=InvalidValue: rejected similarly
    - Config mutation follows same atomic pattern

    **API key regenerate (POST /settings/api-key/regenerate):**
    - Returns partials/security_apikey.html with new 32-char hex key, revealed=True, success="Key regenerated"
    - New key differs from original key
    - Config persisted atomically

    **GET /settings auth context:**
    - Template context includes auth_method, auth_is_disabled, auth_api_key, auth_username
    - auth_api_key is the plain string (SecretStr extracted at template boundary)
  </behavior>

    Add three POST route handlers to routes.py following the setup_post config mutation pattern.
    Extend settings_page GET handler to include auth context variables.
    All endpoints require authentication (already enforced by AuthMiddleware).

    POST /settings/password:
    1. Read form fields: current_password, new_password, confirm_password
    2. Validate: verify_password(current, stored_hash), check new == confirm, check new not empty
    3. On error: return TemplateResponse("partials/security_password.html", errors={...})

    1. Read form field: auth_method
    2. Validate: must be in {"Forms", "Basic", "External"} -- reject "Disabled" and unknown values
    3. model_copy auth with method update, atomic write
    4. RedirectResponse 303 to /settings

    1. generate_api_key()
    2. model_copy auth with new api_key, atomic write
    3. Return TemplateResponse("partials/security_apikey.html", api_key=new_key, revealed=True, success="Key regenerated")

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> POST /settings/password | User-supplied passwords cross into bcrypt verification |
| Browser -> POST /settings/security | User-supplied auth method value must be validated against allowlist |
| Browser -> POST /settings/api-key/regenerate | No user input beyond the POST itself; generates server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-01 | Elevation of Privilege | change_password | mitigate | Always verify current password via verify_password() before accepting new hash |
| T-57-02 | Tampering | save_security | mitigate | Validate auth_method against _ALLOWED_AUTH_METHODS set; reject "Disabled" to prevent downgrade via POST (D-13) |
| T-57-03 | Information Disclosure | settings_page GET | mitigate | Extract api_key via .get_secret_value() only at template boundary; never log raw key (loguru redacting sink) |
| T-57-04 | Tampering | all POST endpoints | accept | CSRF protection via existing OriginCheckMiddleware (validates Origin/Referer on all POSTs) |
| T-57-05 | Information Disclosure | change_password | accept | bcrypt.checkpw is constant-time; no timing oracle on password verification |
| T-57-06 | Denial of Service | change_password | accept | bcrypt is intentionally slow (12 rounds); single-user app, no rate limiting needed (reverse proxy handles brute-force) |
</threat_model>
