<objective>
Flip the runtime over to searched-logs in one coherent commit: remove the cursor fields, strip legacy cursor keys on load, wire all six call sites, and migrate the behavioral cycle tests.

This plan does the work that MUST land together (HIGH-2): it removes `missing_cursor`/`cutoff_cursor` from the `AppState` TypedDict and from `_default_instance_state()`, AND rewires all six cycle call sites (Radarr/Sonarr/Lidarr × missing/cutoff) from the `slice_batch` + cursor mechanics to the thin-caller `prioritize_batch` pattern — in the same plan/commit, so no intermediate state exists where a default instance reads a cursor key that no longer exists. It also fixes HIGH-1: `_merge_defaults` is taught to actively STRIP legacy `missing_cursor`/`cutoff_cursor` keys from each loaded instance dict, so a pre-upgrade `state.json`'s cursor keys are popped on load and never written back (the old "ignored and overwritten on next save" claim was false — `{**defaults, **instance_data}` preserves unknown keys and `save_state` writes them).

Then it migrates the behavioral cycle tests in `test_search.py` (cursor-advancement and network-failure tests) to assert searched-log contents, and adds per-app cycle-integration coverage — including the MANDATORY Sonarr both-queue + Specials integration coverage (MED-2) that proves the composite key is wired correctly at the real `run_sonarr_cycle` sites. It adds the HIGH-1 strip-on-load round-trip test in `test_state.py` (assert legacy cursor keys ABSENT after load→save).

`slice_batch` is NOT removed in this plan (Plan 03 removes it after all callers have migrated and the post-removal cold-start variant exists). `refresh_*_counts` is NOT touched — it must remain queue-independent.

**Why the field removal + strip live here, not in Plan 01:** the six call sites read `ist["missing_cursor"]` until they are rewired. Removing the cursor fields in Plan 01 (a separate commit) would make a default/new instance KeyError mid-cycle between Plan 01 and Plan 02. Landing the field removal, the strip, and the call-site rewrite together eliminates that broken checkpoint. The `_merge_defaults` strip requires nothing of the call sites, so it sits naturally with the field removal.

Purpose: this is the integration that makes the new dispatch live and removes the cursor substrate atomically. Output: cursor fields gone + legacy strip in `state.py`; 6 rewired call sites in `engine.py`; the HIGH-1 strip-on-load test in `test_state.py`; migrated + extended cycle tests (incl. mandatory Sonarr both-queue + Specials) in `test_search.py`.
</objective>
