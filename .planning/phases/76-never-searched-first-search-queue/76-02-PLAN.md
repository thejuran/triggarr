<objective>
Wire `prioritize_batch` into all six cycle call sites and migrate the behavioral cycle tests off the cursor.

This plan replaces the `slice_batch` + cursor-write + wrap-detection mechanics at each of the six call sites (Radarr/Sonarr/Lidarr × missing/cutoff) with the thin-caller pattern: define a per-app `key_fn`, call `prioritize_batch`, write back the searched-log and `*_pass`, and emit one pass-complete INFO line. The per-item search-loop body stays byte-for-byte unchanged. Then it migrates the behavioral cycle tests in `test_search.py` (cursor-advancement and network-failure tests) to assert searched-log contents, and adds per-app cycle-integration coverage (mark-on-attempt, new-item-jumps-line, pass-reset, commit-at-cycle-end).

`slice_batch` is NOT removed in this plan (Plan 03 removes it after all callers have migrated and the post-removal cold-start variant exists). `refresh_*_counts` is NOT touched — it must remain queue-independent.

Purpose: this is the integration that makes the new dispatch live. It is glue/refactor over the pure function from Plan 01, so it is a standard execute plan with tests-as-acceptance-criteria rather than a fresh TDD unit.

Output: 6 rewired call sites in `engine.py`; migrated + extended cycle tests in `test_search.py`.
</objective>
