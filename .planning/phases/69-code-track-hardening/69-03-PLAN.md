<feature>
  <name>Shared _run_one_cycle helper unifying manual + scheduled failure-counter semantics (SAFETY-03)</name>
  <files>triggarr/search/scheduler.py, triggarr/web/routes.py, tests/test_scheduler.py</files>
  <behavior>
    With caller holding app.state.search_lock (the helper itself acquires NO lock), for
    job_id = f"{app_name}_{instance_name}_search":
    - Cycle raises a narrow-tuple exception (httpx.HTTPError / pydantic.ValidationError / aiosqlite.Error):
      → _record_cycle_failure increments app.state.search_failures[job_id] by 1, then returns (no persist).
    - Cycle succeeds but engine sets state[app][inst]["connected"] = False (real *arr outage, no raise):
      → _evaluate_cycle_outcome increments app.state.search_failures[job_id] by 1.
    - Cycle succeeds with connected True/unknown:
      → _evaluate_cycle_outcome resets app.state.search_failures[job_id] to 0; state is persisted via save_state.
    - Persistence raises (OSError / aiosqlite.Error): app.state.persistence_degraded = True, ERROR logged, re-raise
      (counter NOT incremented — durability ≠ transient blip).
    These semantics are IDENTICAL for both the scheduled job() path and the manual search_now path after the refactor.

    Test cases (CHARD-03, in tests/test_scheduler.py, driving _run_one_cycle end-to-end via the real
    MockTransport fixture — NOT patching _record_cycle_failure / _evaluate_cycle_outcome):
    - test_search_now_failure_counter_increment: 503-returning MockTransport; two _run_one_cycle calls
      (each inside `async with app.state.search_lock`) → app.state.search_failures["radarr_Default_search"] == 2
      and state["radarr"]["Default"]["connected"] is False.
    - test_search_now_failure_counter_resets_on_success: first call fails (counter == 1), second call succeeds
      (tag endpoint + empty paginated body) → counter resets to 0.
    - test_search_now_failure_returns_card_200 (HTTP-contract guard): a FAILING manual search through the
      search_now route still returns the app_card partial at HTTP 200, never a 500 — the refactor preserves
      the existing fall-through-to-card contract (RESEARCH Pitfall 3).
  </behavior>
  <implementation>
    See <tasks> below for the RED → GREEN → REFACTOR breakdown. The helper body is a mechanical lift of
    scheduler.py:163-218 (D-03: extraction, not a counter-logic redesign) and acquires NO lock; routes.py
    search_now is rewired to call it inside its already-held lock (69-PATTERNS.md §routes.py shows the exact
    before/after structure). Preserve the HTTP contract: search_now ALWAYS returns the app_card
    TemplateResponse (200), never 500, even on cycle/persistence failure (69-RESEARCH.md Pitfall 3) — the
    outer try/except in search_now wraps _run_one_cycle, logs, and falls through.
  </implementation>
