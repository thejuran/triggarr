## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → public clone | Anything committed (or stray-added) is visible to anyone who clones the public repo |
| developer working tree → `git add -A` | An untracked, non-ignored runtime file can be committed accidentally |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-69-01 | Information Disclosure | `.orchestrator.json` (untracked runtime state) | mitigate | Add to `.gitignore` (Task 1) so a `git add -A` cannot stage orchestrator runtime state into the public repo. Confirmed never committed (`git log --all -- .orchestrator.json` empty), so no history scrub needed — forward prevention only. |
| T-69-02 | Information Disclosure | `.gitleaksignore` (non-functional → secret-scan blind/noisy) | mitigate | Convert to working fingerprint allowlist (Task 2). Risk: an over-broad allowlist could suppress a FUTURE real secret. Mitigation: each fingerprint is commit-SHA-scoped (per-commit, per-line), so it only suppresses the exact known false-positive occurrence; a new real secret in a new commit produces a new fingerprint that is NOT pre-suppressed and will surface in the next scan. All 23 suppressed hits were triaged in 68-FINDINGS.md as `generic-api-key` false positives (test fixtures / doc prose), zero real credentials. |
| T-69-03 | Tampering | repo metadata (no package installs in this plan) | accept | This plan touches only `.gitignore` + `.gitleaksignore`; no npm/pip/cargo installs, no supply-chain surface. No legitimacy gate needed here. |
</threat_model>
