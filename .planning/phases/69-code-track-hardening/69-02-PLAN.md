<objective>
Close P68-FI-002: bump the transitive `starlette` dependency off the vulnerable `0.52.1`
(PYSEC-2026-161 / GHSA-86qp-5c8j-p5mr — a Host-header URL-reconstruction auth-bypass class) to
`>= 1.0.1`. The CVE is closed by adding an EXPLICIT `starlette>=1.0.1` floor to `pyproject.toml`
(alongside a compatible `fastapi` pin), so `uv lock` is forced to resolve the patched starlette
regardless of fastapi's permissive metadata lower bound. The starlette 0.x → 1.x major is a
breakage-risk gate: the bump is only accepted when the FULL test suite is green and ruff is clean
afterward. Because the CVE class is specifically Host-header URL reconstruction → auth bypass, this
plan also adds a focused regression test proving Triggarr's `AuthMiddleware` decision keys off the
routed request path, not an attacker-controlled reconstructed URL.

Purpose: A published CVE in a shipped production dependency is an always-fold-in security finding
(D-04 (b)). Triggarr runs custom auth middleware, so a Host-header/URL-reconstruction auth-bypass class
is directly relevant — close it cleanly via an explicit version floor AND make the security property
verifiable, not merely "the audit is clean."
Output: Updated `pyproject.toml` (explicit `starlette>=1.0.1` + compatible fastapi pin) + regenerated
`uv.lock` resolving starlette >= 1.0.1, a BadHost regression test in `tests/test_auth_middleware.py`,
with the full suite green, ruff clean, and pip-audit CLEAN.
