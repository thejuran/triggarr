<objective>
Add tests proving that `ArrClient.close()` (which delegates to
`httpx.AsyncClient.aclose()`) does not hang when called against requests that are
still in flight at shutdown time. The shutdown drain in `triggarr/search/scheduler.py`
(extended to 60s in plan 65-03) ensures we normally only call `client.close()`
AFTER the lock has drained, but in the worst case (`scheduler.shutdown(wait=False)`
forces cancellation of a running cycle), an in-flight request could still be pending
when `await client.close()` runs.

Purpose: TEST-04. This is the only phase-65 requirement that is pure test work — no
production code changes. The test IS the deliverable. It pins the behavioral
contract we depend on so that a future httpx upgrade that breaks this contract
surfaces as a failing test rather than as a silent shutdown hang in production.

**Revision note (Codex finding 4 — MockTransport is not a production contract).**
The prior draft of this plan used `httpx.MockTransport` for both tests.
`httpx.MockTransport` bypasses the real async connection pool, socket teardown, and
`AsyncHTTPTransport` close logic — the very code paths production exercises during
`AsyncClient.aclose()`. The variant test also accepted "RuntimeError OR
asyncio.CancelledError OR httpx.HTTPError OR clean completion," which proves only
"the mock path does not hang" — not that the production close is safe.

Fix direction (chosen from REVIEWS.md):

1. **Keep the cheap MockTransport unit test for regression coverage** but rename it
   to be honest about what it proves ("mock path does not hang after cancel"). It
   stays for unit-level fast feedback.
2. **Add at least one test using `httpx.ASGITransport`** wired to a minimal Starlette
   `Starlette(routes=[Route("/slow", slow_handler)])` app (or a bare ASGI callable —
   no FastAPI dependency needed). `httpx.ASGITransport` is a real transport that
   exercises the production `AsyncHTTPTransport`-equivalent async machinery
   (connection pool, async streaming, event-loop-aware close).
3. **Tighten the no-cancel acceptance criterion to DETERMINISTIC outcomes** — not
   "accepts any of {RuntimeError, cancellation, HTTPError, clean completion}".
   Run a small live experiment in Task 1 (REPL or scratch script) against the
   installed httpx version to determine the EXACT exception class raised on the
   in-flight task when `aclose()` is called without cancellation. The test then
   asserts that exact class via `isinstance(...)` AND asserts `close()` itself
   returns within 2 seconds.

The `httpx.ASGITransport` approach is preferred over standing up a uvicorn /
aiohttp test server because:
- No extra dependency (`httpx` already required).
- No port allocation, no process management, no flaky cleanup.
- Exercises the real async connection-pool + close machinery in `httpx`.

Output:
- `tests/test_clients.py` — three new tests:
  - `test_aclose_with_mocktransport_returns_quickly_after_cancel` (renamed unit
    test, keeps the cheap regression coverage),
  - `test_aclose_with_real_asgi_transport_in_flight_returns_within_2s` (new
    real-transport contract test — the cancel-then-close happy path),
  - `test_aclose_with_real_asgi_transport_no_cancel_raises_specific_exception`
    (new real-transport contract test — pins the exact exception type httpx surfaces

No production code changes.

httpx.MockTransport accepts ASYNC handlers since httpx 0.20 (verified at REPL in
RESEARCH §F / Assumption A2).

**New: httpx.ASGITransport** — wraps an ASGI app for in-process HTTP testing.
Constructor: `httpx.ASGITransport(app=<asgi_callable>)`. The wrapped client uses
real `AsyncHTTPTransport`-style connection pool + async streaming, just terminating
inside the ASGI app instead of at a real socket. Available in httpx 0.20+
(Triggarr's `pyproject.toml` pins httpx>=0.27 — confirm with `uv run python -c
"import httpx; print(httpx.__version__)"`). Documented at
https://www.python-httpx.org/async/#calling-into-python-web-apps.

Minimal ASGI app shape (no framework dependency required):

A pure-async callable `async def app(scope, receive, send)` with three branches:
- If `scope["path"] == "/slow"`: signal an `asyncio.Event` (so the test knows the
  request reached the handler), then `await asyncio.sleep(10)` (blocks until
  cancelled). Never sends a response in time.
- If `scope["path"] == "/fast"`: send `{"type": "http.response.start", "status":
  200, "headers": []}` then `{"type": "http.response.body", "body": b'{"ok":true}',
  "more_body": False}`. Used as a sanity check that the transport works.
- Otherwise: 404.

Alternative: a small Starlette app — but adding `starlette` as a test dep is
overkill. The bare ASGI callable above is ~20 lines of test-local helper code.
