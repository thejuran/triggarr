<objective>
Add tests proving that `ArrClient.close()` (which delegates to
`httpx.AsyncClient.aclose()`) does not hang when called against requests that are
still in flight at shutdown time. The shutdown drain in `triggarr/search/scheduler.py`
(extended to 60s in plan 65-03) ensures that we normally only call `client.close()`
AFTER the lock has drained, but in the worst case (`scheduler.shutdown(wait=False)`
forces cancellation of a running cycle), an in-flight request could still be pending
when `await client.close()` runs.

Purpose: TEST-04. This is the only phase-65 requirement that is pure test work — no
production code changes. The test IS the deliverable. It pins the behavioral
contract we depend on (httpx surfaces a `RuntimeError` rather than blocking, and the
recommended pre-cancel-then-close pattern returns within 2 seconds) so that a future
httpx upgrade that breaks this contract surfaces as a failing test rather than as a
silent shutdown hang in production.

Output:
- `tests/test_clients.py` — two new tests:
  - `test_aclose_does_not_hang_with_in_flight_requests` — proves the
    cancel-then-close pattern returns within 2s.
  - `test_aclose_raises_when_requests_in_flight` — proves the documented
    httpx behavior (RuntimeError or clean completion within 2s when close is
    called WITHOUT cancelling first).

No production code changes.
</objective>
