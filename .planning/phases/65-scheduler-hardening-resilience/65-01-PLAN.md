<objective>
Narrow the over-broad `except Exception` at the outer try in `make_search_job` to the
canonical four-type tuple `(httpx.HTTPError, pydantic.ValidationError, aiosqlite.Error,
OSError)` used 22 times in `engine.py`, and wire an APScheduler `EVENT_JOB_ERROR`
listener so that exceptions which now propagate (RuntimeError, KeyError, MemoryError,
etc.) become operator-visible at ERROR level instead of disappearing into APScheduler's
stdlib-logging silence.

Purpose: SAFETY-02. Today, a code-bug exception (e.g. AttributeError from a refactor)
is silently swallowed by `except Exception`. After this plan, code bugs surface in the
log; transient external-service failures (the four narrow types) continue to be caught
gracefully so the scheduler keeps running.

Output:
- `triggarr/search/scheduler.py` — narrowed outer except tuple in `make_search_job`,
  module-level imports for `apscheduler.events.EVENT_JOB_ERROR` and `_sanitize_exc`,
  plus `scheduler.add_listener(_on_job_error, EVENT_JOB_ERROR)` call before
  `scheduler.start()`.
- `tests/test_scheduler.py` — existing `test_make_search_job_exception_swallowed`
  renamed and inverted to `test_make_search_job_unexpected_exception_propagates`; new
  sibling `test_make_search_job_httperror_swallowed`; new
  `test_event_job_error_listener_logs_unexpected_exception` covering the listener.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-01 | Information Disclosure | `_on_job_error` listener logging `event.exception` | mitigate | Listener routes `httpx.HTTPError`/`pydantic.ValidationError` through `_sanitize_exc()` (engine.py:30) which strips `request.url` (may contain `apikey=`); other exception types log `str(exc)` because Triggarr's non-httpx exceptions do not carry secrets |
