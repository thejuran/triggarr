Middleware exemption (middleware.py:118 — NO change needed, and EXEMPT_PREFIXES is NOT touched): the dispatch predicate is
  path == "/reset" or path.startswith("/reset/") or any(path.startswith(p) for p in EXEMPT_PREFIXES)
EXEMPT_PREFIXES stays exactly ("/health", "/static", "/login", "/setup") (middleware.py:25). /reset/confirm is exempt via startswith("/reset/"). Do NOT add "/reset" to EXEMPT_PREFIXES (that would over-expose /resetXYZ); the exact-or-/reset/ predicate deliberately keeps /resetXYZ gated.

GATED-response shape for a NON-exempt unauthenticated path (verified against middleware.py dispatch, step 7, lines 160-164): when a configured app (needs_setup=False, method="Forms", no session cookie, no api-key) receives a request to a path the exemption does NOT cover (e.g. /resetXYZ), dispatch falls through to the fallback and returns:
- 302 RedirectResponse to "/login?next=..." (with "/login" in the Location header) when the request is a browser request (`Accept: text/html` present — `_is_browser` True), OR
- 401 JSONResponse {"detail": "Authentication required"} for a non-browser request.
It NEVER returns 404 when gated. A 404 would only occur if the path bypassed AuthMiddleware and reached the router (no matching route) — i.e. the exemption widened. Therefore 404 must NOT be treated as a gated/passing status in the regression test below.

- empty new password   -> errors["new_password"] = "New password is required"
- mismatch             -> errors["confirm_password"] = "Passwords do not match"
- over 72 bytes        -> errors["new_password"] = "Password must be 72 characters or fewer"
