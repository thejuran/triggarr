# Phase 20.1 Plan 02: Security Fixes Summary

**XSS-safe URL attributes with urlencode filter, race-free rate limiter with double-checked locking, type-based exception sanitization, and sourceTitle truncation**

## Performance

## Accomplishments
- Applied `| urlencode` filter to all 4 dynamic value locations in hx-get URL attributes (lines 19, 42, 65, 129) preventing reflected XSS via search_text injection
- Restructured rate limiter in `search_now` to write timestamp inside `search_lock` with re-check, closing TOCTOU race that allowed concurrent bypass
- Added `_sanitize_exc` helper producing safe type-based summaries (HTTP status codes, "request timeout", type names) instead of raw `str(exc)` that could leak paths/URLs/keys
- Truncated external `sourceTitle` from *arr API to 200 chars before storage in search history detail field
- Added test for concurrent rate limit protection and 3 tests for exception sanitization covering HTTPStatusError, TimeoutException, and generic exceptions

## Task Commits

## Files Created/Modified

- `fetcharr/search/engine.py` - Added `_sanitize_exc` helper, replaced all 4 `str(exc)[:200]` with `_sanitize_exc(exc)`

## Decisions Made
- Applied urlencode to ALL dynamic values in hx-get attributes (not just `search_text`) for defense-in-depth, even though filter pill values are safe hardcoded strings
- Used type-based dispatching in `_sanitize_exc` to provide useful context (HTTP status codes, error counts) while excluding raw messages that may contain sensitive data
- Kept optimistic pre-lock check for fast-fail performance (avoids lock contention for obvious rate-limited requests) while adding authoritative re-check inside lock for correctness
