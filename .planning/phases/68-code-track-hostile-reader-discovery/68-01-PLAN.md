Run a deliberate "this is on Reddit and a skeptical r/selfhosted engineer is reading it" hostile pass over Triggarr's whole code surface, its launch-visible self-hosting surface (Docker/compose/entrypoint/templates/htmx/middleware/CI), AND its full git history across all refs, then capture and classify every result into one authoritative triaged findings artifact, `68-FINDINGS.md`. The classification produced here is the gate that defines Phase 69's fix scope. The full-history, all-refs git scan is the launch-visible-risk addition unique to an already-public repo with a long commit history.

<classification_bar>
<!-- LOCKED in 68-CONTEXT.md D-04. Apply to EVERY finding. -->
FOLD-IN if: (a) launch-visible — something a skeptical r/selfhosted engineer browsing the repo / README / `git log` would actually see and ding — OR (b) any real security or secret exposure, regardless of visibility.
PARK if: pure-internal nitpick (style the linter doesn't enforce, invisible debt, cosmetic item) — with written rationale.

HARD RULE (NARROWED per F-5): The pre-park applies ONLY to the exact pre-parked shape — "the config setting EXISTS in the model but is NOT exposed in the settings UI" (DEBT-03 history cap, DEBT-06 drain timeout, DEBT-07 request timeout, DEBT-08 page size; UI-01/02/03 auth-page pixel verification). That specific UI-exposure debt MUST NOT be folded in even if a tool surfaces it; record it PARKED with rationale "spec D-5: UI-exposure debt, invisible to launch reader, parked to v2."
TIEBREAKER (F-5): An INDEPENDENT security, secret, runtime-correctness, or launch-visible finding that merely happens to touch the same file or the same setting still applies the D-04 bar normally and CAN be FOLD-IN. Only the UI-exposure debt ITSELF is forced PARKED. Example: a real bug in `config.py` is NOT auto-parked just because DEBT-07 also lives in `config.py`. The pre-park gates the missing-UI-knob, not the file.
</classification_bar>

<source_classification_matrix>
<!-- F-8: source-specific tiebreaker matrix. Apply alongside the D-04 bar. -->
FOLD-IN sources: any security finding, any secret exposure, any runtime-correctness defect, any user-visible failure (crash, wrong result, broken install/quickstart, leaked internals in a response).
PARKED sources (unless they produce a visible failure): pure style the linter does not enforce, import-ordering (ruff I), pyupgrade modernization (ruff UP) with no behavior change, test-only cleanup.
AMBIGUOUS: if a finding does not cleanly fall into either bucket, it requires a written one-sentence "why a Reddit reviewer would notice" justification BEFORE it may be marked FOLD-IN. With no such justification it is PARKED.
</source_classification_matrix>

<tool_contract>
<!-- F-2 + F-3: structured-output + finding-exit-code contract for ALL FOUR tools. -->
STRUCTURED OUTPUT IS THE CONTRACT. Each tool emits machine-readable JSON; capture it, then classify rows from it.
- ruff:      `uv run ruff check triggarr/ tests/ --output-format json`
- semgrep:   `semgrep scan --json --config auto triggarr/`   (the SAST tool Shield wraps)
- gitleaks:  `--report-format json --report-path <path> --redact`  (working-tree AND full-history runs)
- pip-audit: `uv run pip-audit --format json`   (fall back to `pip-audit --format json` if `uv run` is unavailable)

EXIT-CODE SEMANTICS (CRITICAL): ALL FOUR tools use a NON-ZERO exit code to mean "findings exist," NOT "the command failed." gitleaks defaults to exit code 1 when leaks are found; ruff, semgrep, and pip-audit likewise return non-zero on findings.
- A finding-exit-code is SUCCESS-WITH-FINDINGS: capture the JSON, parse the rows, classify them. NEVER silently abort the task on a non-zero exit.
- A GENUINE failure (tool-not-found, flag rejected, parse error, crash, segfault) is a DISCOVERY FAILURE: record it SEPARATELY in the source section's "Discovery status" line (e.g. "DISCOVERY FAILURE: gitleaks rejected --log-opts; section inconclusive") and do not pretend the source ran clean. A discovery failure on a required source FAILS the phase verify gate — it is not a clean result.
- In every source section, record the exact command actually invoked and its exit code so the run is reproducible and a finding-exit vs. a real failure is unambiguous.
</tool_contract>
