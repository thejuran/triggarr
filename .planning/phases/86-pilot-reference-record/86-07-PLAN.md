<objective>
Push both pilot PRs in one batch, open them ready for review, post per-head checkpoint comments, and take the first (Refresh-counts) through exact-commit owner acceptance; the owner merges it. The second PR's integration with the updated main and its acceptance are 86-10.

Purpose: PILOT-01 needs the two new PRs actually run through the full current process, ending in owner acceptance (D-04). Batching the two pushes follows the push-budget practice.
Output: Two open pilot PRs with per-head checkpoint comments, the first accepted and merged by the owner; durable copies, PR numbers, runs and the first merge commit recorded on the phase branch.

Why serialized: the ruleset requires strict/current status checks (docs/buildomator-greptile-pilot.md: "strict/current `CI ready`"). Both branches start from the same main, so once the first merges, the second is behind main and its checks and evidence no longer describe the head that would merge.

Claude never merges, never approves acceptance itself and never infers approval (CLAUDE.md "Active owner approval through Claude CLI"; docs/owner-cli-acceptance.md Authorization boundary). Records are written on `phase-86-pilot-reference-record`; any fix commit goes on the affected pilot branch only.
</objective>
