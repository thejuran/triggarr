## Warnings

### WR-01: No card test checks that the template uses `kind` (confirmed by restoring the old template)

**File:** `triggarr/templates/partials/cycle_grade.html:20-24`, `tests/test_app_cards.py` (unchanged)
**Issue:** Commit `1fb66b9` ("pin structured reason kind on cycle card rows") only checks the dict that `cycle_view` returns, in `tests/test_outcome.py`. No test renders the card with a record where text-based and kind-based grouping would give different results. I confirmed this by restoring the `d5a4467` version of `cycle_grade.html` in a throwaway copy of the tree: `tests/test_app_cards.py` + `tests/test_outcome.py` still gave 148 passed. The point of this change (D-03: the card must not depend on display wording) is therefore not protected where it matters, in the rendered summary label.

Here is a real record that shows the two approaches giving different results. It is a tampered or inconsistent record that `cycle_view` accepts. Use `failed: 0`, the legacy `malformed_skipped: 1`, and a `failure_reasons` entry whose text gets cut at 120 characters so that it ends in `skipped`. The old template counts the failure row as malformed: `int('Search')` gives 0, so the total still equals `malformed_skipped`, and the summary reads "Show 1 skipped record" above a "Search command … failed" row. The new template counts that row as `other` and shows "Show 2 failure reasons".
**Fix:** Add a card-level test to `tests/test_app_cards.py` that fails under the old template, for example:
```python
def test_card_groups_by_kind_not_text(client, test_app):
    """D-03: a failure row whose truncated text ends in 'skipped' is still a failure."""
    prefix = "Search command to Radarr failed ("
    reason = "x" * (120 - len(prefix) - len(" skipped")) + " skipped trailing"
    _set_last_cycle(test_app, {  # use the module's existing helper for seeding last_cycle
        "grade": "partial", "accepted": 1, "failed": 0, "malformed_skipped": 1,
        "failure_reasons": [{"reason": reason, "count": 1}],
    })
    text = client.get("/").text
    assert "Show 2 failure reasons" in text
    assert "skipped record" not in text
```
Run it once against the `d5a4467` template to confirm that it fails there.

## Info

### IN-01: Reason `kind` values are plain string literals copied across Python, the template and the tests

**File:** `triggarr/search/outcome.py:267,283,300,316,324,345`; `triggarr/templates/partials/cycle_grade.html:20,22`; `tests/test_outcome.py:707`
**Issue:** The five kind names exist only as inline string literals, with no shared constant or `Literal` type. A typo or rename on either side does not raise an error. A row whose kind does not match falls through to `ns.other` and quietly changes the summary label to "failure reasons". Together with WR-01, nothing would catch that drift.
**Fix:** Define the names once, e.g. `REASON_KINDS` / `ReasonKind = Literal["fetch_failed", "failure", "unevaluated", "malformed", "eligible_not_searched"]` plus module constants in `outcome.py`. Use them at the six places that add rows, and import them in `tests/test_outcome.py` instead of re-declaring `_ALLOWED_REASON_KINDS`.

### IN-02: The all-kinds test hard-codes part of the result it is meant to check

**File:** `tests/test_outcome.py:747`
**Issue:** `all_kinds_seen = kinds_seen | {"malformed"} | {...view_eligible...}` adds `"malformed"` as a literal instead of taking it from `view_legacy`. The earlier line `assert kinds_seen <= _ALLOWED_REASON_KINDS` is redundant with the equality check after it. The docstring also says kinds are "never derived from display text", which a dict-level test cannot show (see WR-01).
**Fix:** Use `{r["kind"] for r in view_legacy["reasons"]}` in place of the literal, drop the redundant subset check, and move the "not derived from display text" claim to the render test proposed in WR-01.

## Set aside (needs ruling)

### SA-01: The eligible-not-searched fallback row ignores per-queue malformed rows

**Where:** `triggarr/search/outcome.py:328-335`
**Why excluded:** This code existed before this change and the diff did not touch it. The guard checks `malformed_skipped == 0`, but not `malformed_rows_appended == 0`.
**Effect if left as is:** Only an inconsistent or tampered record triggers it: `grade: failed`, `accepted/failed: 0`, `malformed_skipped: 0`, a non-empty `malformed_by_queue`, and eligible > 0. The card then shows both the "N … records skipped — malformed data" rows and an "N eligible items not searched this cycle" row, which give two different explanations for one cycle. Records produced by the engine itself do not hit this.
**Needs:** A ruling: tighten the guard to `malformed_rows_appended == 0` in a later phase, or accept the behavior.
