  <behavior>
    parseReleaseTag (D-21):
    - "refs/tags/v2.13.0" -> "2.13.0"; "refs/tags/v0.0.0" -> "0.0.0"; "refs/tags/v10.20.30" -> "10.20.30"
    - rejects with /malformed/: "refs/tags/v2.13", "refs/tags/v2.13.0.1", "refs/tags/2.13.0", "refs/tags/v2.13.0-rc1", "refs/tags/v2.13.0+build5", "refs/tags/v02.13.0", "refs/tags/v2.013.0", "refs/tags/v2.13.00", "refs/heads/main", "", undefined, "refs/tags/v2.13.0\n", "refs/tags/V2.13.0", "refs/tags/v-1.0.0"
    - rejection message names the raw ref and says "package: not inspected" and "image: not inspected" (D-23)
    parseProjectVersion:
    - the real repo pyproject.toml text (read with fs in the test) -> its [project] version
    - a [project] table with version = "1.2.3" followed by [project.optional-dependencies] containing a version-looking line -> "1.2.3" (only the [project] table counts)
    - rejects with /package version/: no [project] table; [project] without version; two version lines in [project]; version = "" ; version not a double-quoted string
    validateReleaseIdentity (D-17, D-23):
    - ref v1.2.3, packageVersion "1.2.3", imageVersion "1.2.3" -> "1.2.3"
    - mismatch with package (package "1.2.4") -> throws /disagree/ and the message contains "tag: 1.2.3", "package: 1.2.4", "image: 1.2.3"
    - mismatch with image (image "1.2.2") -> throws /disagree/ with all three values
    - imageVersion undefined -> throws and message contains "image: not inspected"
    - imageVersion "" (inspected, label missing) -> throws /missing/ and message contains "image: missing"
    - packageVersion undefined -> "package: not inspected"; "" -> "package: missing"
    - malformed ref -> the parseReleaseTag rejection (no comparison attempted)
    releaseIdentityGate:
    - fake github whose repos.getContent returns {data:{content: base64(pyproject text), encoding:'base64'}} for {owner, repo, path:'pyproject.toml', ref: sha} -> resolves to the version, records exactly one getContent call with those args, calls core.info once
    - sha not 40 lowercase hex -> rejects /Invalid release commit/ before any API call
    - getContent throws -> rejects with the API error, core.info never called
    - getContent returns non-base64 encoding or a directory array -> rejects /package version/
    - image label mismatch -> rejects /disagree/
  </behavior>
  <implementation>
    Follow validateEvidence's style: destructured single-object args, guard clauses throwing new Error with a specific reason, plain return values. Build one internal helper (e.g. describeVersions({tag, packageVersion, imageVersion})) that renders "(tag: X, package: Y, image: Z)" mapping undefined -> "not inspected" and "" -> "missing", and append it to every rejection message. Tag grammar is the D-21 regex: ^refs/tags/v(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$ — no semver library (Don't Hand-Roll). parseProjectVersion scans lines: find the line exactly "[project]", collect lines until the next line starting with "[", match ^version\s*=\s*"([^"\\]+)"\s*$ ; exactly one match required. Values interpolated into messages are tag/version strings only — never tokens.
  </implementation>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git tag ref -> release policy | A pushed tag name is attacker-influenceable text (anyone with push rights, or a typo) |
| GitHub contents API -> release policy | pyproject.toml text at the release commit is data from the repository |
| Docker image label -> release policy | The label value comes from the audited artifact, read in the release job |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-01 | Tampering | parseReleaseTag | mitigate | Full-string anchored D-21 regex; rejects pre-release, build metadata, leading zeros, trailing newline and case variants; tested with literal malformed inputs |
| T-82-02 | Spoofing | validateReleaseIdentity | mitigate | Publishing requires tag == package == image label; mismatch or missing value throws (fail closed) |
| T-82-03 | Repudiation | rejection messages | mitigate | Messages name the reason and all available values, "not inspected"/"missing" instead of invented values (D-23) |
| T-82-04 | Tampering | policy source | mitigate | Functions live in release-policy.cjs, which release.yml loads from main via sparse checkout; no code is read from the tag |
| T-82-05 | Denial of Service | releaseIdentityGate API call | accept | An API outage blocks a release (fails closed); retrying the release run is an owner action |
| T-82-06 | Information Disclosure | error messages | mitigate | Only tag and version strings are interpolated; no tokens or headers are included |
</threat_model>
