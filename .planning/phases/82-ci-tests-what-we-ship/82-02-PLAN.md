<feature>
  <name>CI harness: stub *arr service and reason-coded HTTP checks</name>
  <files>tests/harness/__init__.py, tests/harness/arr_stub.py, tests/harness/checks.py, tests/test_ci_harness.py</files>
  <behavior>
    arr_stub (build_server(host, port, api_key) -> ThreadingHTTPServer; serve via thread in tests):
    - GET /api/v3/system/status with correct X-Api-Key -> 200 JSON containing "version" string
    - GET /api/v3/wanted/missing, /api/v3/wanted/cutoff, /api/v3/movie -> 200 envelope with totalRecords 0 and records []
    - GET /api/v3/tag -> 200 []; GET /api/v3/history/movie -> 200 []; POST /api/v3/command -> 201 JSON with an integer id
    - any /api/ request with missing or wrong X-Api-Key -> 401
    - POST /__control/state body {"up": false} -> 200 {"up": false}; afterwards every /api/ request -> 503; {"up": true} restores 200
    - GET /__control/state -> 200 {"up": <bool>, "api_requests": <int>} where api_requests counts /api/ requests received
    - POST /__control/state with non-boolean "up" or invalid JSON -> 400, state unchanged
    - unknown path -> 404
    - the stub never echoes or logs request headers
    checks (each raises SmokeCheckError(reason, detail) on failure; tested against a local fake server whose responses each test controls):
    - check_health: 200 {"status":"ok"} passes; 500, non-JSON, or wrong JSON -> reason "health"
    - check_static_assets: 200 non-empty bodies for all default assets pass; a 404 or empty body for any one -> reason "static-asset-missing" and the detail names the path
    - check_setup_available: 200 containing name="confirm_password" passes; otherwise reason "setup-unavailable"
    - complete_setup(base, username, password): 200 + triggarr_session cookie -> returns the cookie value; missing cookie -> reason "setup-failed"
    - check_setup_closed: 302 with Location containing /login passes; 200 -> reason "setup-still-open"
    - check_login_rejected(base, username, wrong_password): 200 containing "Invalid username or password" and no session cookie passes; a session cookie issued -> reason "login-accepted-wrong-password"
    - login(base, username, password): 303 + cookie -> cookie value; anything else -> reason "login-failed"
    - check_dashboard(base, cookie): 200 containing "Dashboard - Triggarr" passes; 302 -> reason "dashboard-unreachable"
    - check_protected_redirects_to_login(base): no cookie, Accept text/html, GET / -> 302 with Location containing /login passes; otherwise reason "protected-page-open"
    - no check sends an Origin or Referer header, and redirects are never followed automatically
    - expect_failure("static-asset-missing", fn, ...) passes when fn raises that reason; raises SmokeCheckError reason "negative-harness" if fn returns normally or raises a different reason
    - SmokeCheckError str() is "[<reason>] <detail>" and never includes passwords or cookie values (detail strings in tests are asserted not to contain the password/cookie used)
  </behavior>
  <implementation>
    Stdlib only in both modules (http.server, urllib.request, http.cookies, json, threading) so arr_stub.py can run inside the shipped image's Python with no extra packages (Plan 04 mounts it read-only into a stub container). arr_stub.py also has a main() reading --host/--port and the API key from env STUB_API_KEY, guarded by if __name__ == "__main__". Override BaseHTTPRequestHandler.log_message to a no-op so no request lines or headers are written. checks.py uses a urllib opener with a no-redirect HTTPRedirectHandler subclass and explicit timeouts (10s). Use loguru (project convention) only for progress lines that contain no credentials. Python conventions: from __future__ import annotations, module docstrings, snake_case, ruff-clean at line length 120.
  </implementation>
</feature>
