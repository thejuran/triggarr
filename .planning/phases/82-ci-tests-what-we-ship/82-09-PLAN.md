<objective>
Record the negative evidence for Phase 82 in two clearly separated kinds (D-32):
(i) browser sensitivity evidence: the real browser assertions fail on each pill mutation, shown by running the real suite against template-only variants of the exact audited CI image in a labelled local demonstration setting (no push);
(ii) aggregate-gate enforcement evidence: on isolated draft PRs after the owner's go-ahead (D-10), a failing or skipped mandatory job keeps CI ready red (broken entrypoint via image-smoke; pill mutations via the existing header unit tests in the test job).

Why this mechanism for (i): tests/test_header_redesign.py (lines 268-286) rejects both pill mutations in the test job, and docker needs test, so a pushed mutation can never reach browser-e2e. Getting the browser job to run on a pushed mutation would require weakening or skipping those header tests or altering CI wiring, which D-32 forbids. Building the variant FROM the exact audited image changes nothing but the template file(s), so the browser test sees the shipped artifact plus only the regression under test, with the same test files, harness and flags CI uses. The claim it supports ("the real browser assertions detect these regressions in the shipped image") is narrow, which D-07 allows locally; gate enforcement comes from (ii) on GitHub.

Output: 82-DEMONSTRATIONS.md with both evidence kinds and the CISHIP-03 section. Per D-31e no deliberately red tag-triggered run is performed or required. Owner acceptance through review-acceptance is a separate later step on the final head (D-35) and is not part of this plan.
</objective>
