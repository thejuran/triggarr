<objective>
Cap the pre-upgrade database backups that `run_migrations` writes during a crash-looping failed upgrade: keep the canonical `.v{current}-backup` plus at most the 3 most recent timestamped `.v{current}-backup-{stamp}` copies, ordered by the stamp in the file name, with a pruning failure logged and never blocking startup.

Feature: today every repeated failed attempt from the same schema version writes another full timestamped copy of the database (`triggarr/db.py::run_migrations`, the `backup_path.exists()` branch) and nothing ever removes them, so a container restart loop fills the disk. Add one private helper that runs right after the new timestamped copy is written.
