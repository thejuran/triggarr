Cache *arr tag-list responses in `app.state.tag_cache` with a 1-hour TTL keyed per (app_name, instance_name), eliminating the per-cycle `get_tags()` round-trip for tag-filtered instances; invalidate the relevant entry when instance config changes or an instance is removed (RES-03).

Purpose: Tag resolution no longer adds a network round-trip on every scheduled cycle.
Output: A module-level TTL constant + tag_cache init + a cache-resolving callable threaded into the engine cycle fns, plus targeted invalidation in the settings-save and remove-instance handlers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| *arr API → tag_cache | Tag list responses stored in process memory |
| settings form → save_settings → tag_cache | Config change triggers cache invalidation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-03 | Tampering | tag_cache poisoning via failed fetch | mitigate | Resolver does NOT catch exceptions; only a successful `get_tags()` reaches the store line, so a transient *arr outage cannot pin an empty/poisoned tag list for the TTL window (D-07, Pitfall 2/3). |
| T-67-04 | Tampering | stale cache after config change | mitigate | save_settings invalidates the changed instance's entry under search_lock before the next cycle; remove_instance clears its entry — prevents serving tags for a since-changed url/api_key. |
| T-67-07 | Tampering | stale tags served to a reused instance name after form-removal | mitigate | save_settings ALSO pops the cache for instances removed/disabled via form omission (the 614-623 removal loop, Codex finding B), so a new instance reusing a removed name within the 1h TTL cannot receive the prior instance's cached tags. |
| T-67-05 | Information Disclosure | tag_cache contents | accept | LOW — cache stores `list[Tag]` (tag id/label), never the API key or any SecretStr; the cache key contains instance_name (not the secret). No credential leakage. |
| T-67-06 | Tampering | cross-instance cache bleed | accept | LOW — cache key is the `(app_name, instance_name)` tuple, so one instance's tags can never be served for another instance (D-05 keying). |
| T-67-SC | Tampering | npm/pip/cargo installs | n/a | No package installs (RESEARCH.md: no new dependencies). |
</threat_model>
