# Phase 20.1 Context: Deep Review — Security & Safety

## Phase Goal
All security vulnerabilities and data-correctness bugs identified by deep code review are resolved before shipping.

## Origin
These issues were found by `/deep-review` run on 2026-02-25 after completing Phase 20 (Tracking Integration). Five parallel review agents (Bugs, Security/OWASP, Architecture, CLAUDE.md Compliance, Python) analyzed the full v2.0 diff (9,145 lines added across 28 Python files).

## Issues Addressed (8 fixes, 2 plans)

### Plan 1: DB Safety Fixes (DRSEC-01, DRSEC-04, DRSEC-05, DRSEC-06)

**DRSEC-01 — row_factory race condition** (Warning, confidence 88)
- `db.row_factory = aiosqlite.Row` set/reset on shared connection without try/finally
- Concurrent coroutines can interleave, leaving factory in wrong state
- Files: `fetcharr/db.py` (lines 224, 231, 298, 317, 352, 360)
- Fix: Wrap in try/finally, or set row_factory on cursor instead of connection

**DRSEC-04 — Migration backup crash on fresh install** (Warning, confidence 90)
- `shutil.copy2(db_path, backup_path)` raises FileNotFoundError when db_path doesn't exist
- File: `fetcharr/db.py` (line 60)
- Fix: Guard with `if db_path.exists()`

**DRSEC-05 — v4 migration backfill incorrectness** (Warning, confidence 92)
- v1 sets `outcome DEFAULT NULL`; v4 sets all NULL outcomes to 'unresolved'
- Catches legitimately pending rows, not just pre-v1 rows
- Files: `fetcharr/db.py` (lines 79, 114)
- Fix: Change v1 DEFAULT from NULL to 'searched'

**DRSEC-06 — suppress(Exception) too broad** (Warning, confidence 88)
- `contextlib.suppress(Exception)` in _migrate_v1 and _migrate_v2
- Silently swallows disk-full, corruption, permission errors
- File: `fetcharr/db.py` (lines 78, 86)
- Fix: Narrow to `sqlite3.OperationalError`

Also in Plan 1:
- **DRQUAL-09** — get_schema_version unclosed cursor (Medium, confidence 72)
- **DRQUAL-07** — Migration loop KeyError on version gaps (Warning, confidence 80)

### Plan 2: Security Fixes (DRSEC-02, DRSEC-03, DRSEC-07, DRSEC-08)

**DRSEC-02 — Reflected XSS in template URLs** (Warning, confidence 85)
- `search_text` interpolated in `hx-get` URL attributes without urlencode
- Jinja2 auto-escaping doesn't URL-encode within attributes
- File: `fetcharr/templates/partials/history_results.html` (lines 19, 42, 65, 129)
- Fix: Apply `| urlencode` to all dynamic values in hx-get URLs

**DRSEC-03 — Rate limiter check-then-act race** (Warning, confidence 85)
- Timestamp written before search_lock acquired
- Two concurrent requests can both pass rate limit check
- File: `fetcharr/web/routes.py` (line 376)
- Fix: Move timestamp write inside `async with search_lock`, re-check after acquiring

**DRSEC-07 — Raw str(exc) bypasses log redaction** (Medium, confidence 78)
- Exception messages stored in SQLite `detail` field and rendered in UI
- Bypasses loguru redacting sink; could expose internal paths/URLs
- File: `fetcharr/search/engine.py` (lines 246, 280, 397, 436)
- Fix: Use type-based summary (e.g., `f"HTTP {exc.response.status_code}"`)

**DRSEC-08 — sourceTitle not truncated** (Medium, confidence 80)
- `sourceTitle` from *arr API written to `detail` without length limit
- engine.py truncates to 200 chars, but tracking.py doesn't
- File: `fetcharr/tracking.py` (line 169)
- Fix: Apply `[:200]` truncation
