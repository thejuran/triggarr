### Plan 1: Tracking & Correlation Cleanup (DRQUAL-01 through DRQUAL-06, DRQUAL-08)

**DRQUAL-01 — Missing type annotations** (Warning, confidence 95)
- `run_tracking_check`: db, radarr_client, sonarr_client untyped

- `_radarr_outcome`, `_sonarr_outcome`: `matched_grabs: list` not `list[GrabEvent]`
- File: `fetcharr/tracking.py` (lines 19-24, 123, 163, 185)
- Fix: Add full annotations

**DRQUAL-02 — Pass counter off-by-one** (Warning, confidence 95)

- File: `fetcharr/search/engine.py` (lines 253, 287, 406, 445)
- Fix: Change default from 1 to 0

Note: Although engine.py is in Plan 1 here, it's grouped with tracking fixes because the pass counter is a correctness issue related to search cycle behavior.

**DRQUAL-04 — Duplicate tracking log** (Medium, confidence 90)
- Near-identical `logger.info` in both `tracking.py:113` and `scheduler.py:79`
- Fix: Remove from `tracking.py`, keep conditional log in scheduler

**DRQUAL-05 — Naive datetime accepted** (Warning, confidence 77)
- `SearchRecord.searched_at: datetime` — no timezone enforcement
- Comparing naive vs aware datetimes raises TypeError at runtime
- File: `fetcharr/correlation.py` (lines 17-30)

**DRQUAL-06 — `or 0` conflates None and 0** (Medium, confidence 78)
- `expected = missing_count or 0` treats int 0 same as None
- File: `fetcharr/tracking.py` (line 190)

**DRQUAL-08 — Dead branch in _sonarr_outcome** (Medium, confidence 78)

- File: `fetcharr/tracking.py` (line 200)
