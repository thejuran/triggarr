Create a new module `fetcharr/tracking.py` with one main async function:

**`async def run_tracking_check(db, radarr_client, sonarr_client, tracking_window_minutes) -> dict[str, int]`**

Parameters:
- `db: aiosqlite.Connection` -- shared DB connection
- `radarr_client: RadarrClient | None` -- None if Radarr not enabled
- `sonarr_client: SonarrClient | None` -- None if Sonarr not enabled
- `tracking_window_minutes: int` -- from settings.general.tracking_window_minutes

Returns a dict with counts: `{"grabbed": N, "partial": N, "unresolved": N, "errors": N}` for logging.

**Algorithm:**

1. Call `get_trackable_entries(db)` to get all pending entries.
2. Check current time. For each entry, compute `window_end = searched_at + tracking_window_minutes`.
3. Group entries by `(app, item_id)` -- all entries for same item share one API call.
4. For each group:
   a. If the corresponding client is None, skip (app not enabled).
   b. Try to call `client.get_grab_history(item_id)`. On httpx.HTTPError or pydantic.ValidationError, log warning and skip this group (entries stay "searched"). Increment error count.
   c. Build `SearchRecord` list from entries. Call `correlate_grabs(searches, grabs, tracking_window_minutes)`.
   d. For each CorrelationResult, determine the new outcome:

**Radarr outcome logic** (binary, app == "Radarr"):
- If grab_count > 0: outcome = "grabbed"
  - detail = f"grabbed: {result.matched_grabs[0].sourceTitle}" (first grab's sourceTitle)
  - stat_increments: if queue_type == "missing" -> {"movies_found": 1}, if "cutoff" -> {"movies_updated": 1}
- Else if window expired (now > window_end): outcome = "unresolved"
  - detail = "no grabs detected within tracking window"
  - stat_increments = None (no stats on unresolved)
- Else: skip (still within window, leave as "searched")

**Sonarr outcome logic** (three-state, app == "Sonarr"):
- entry.missing_count is the expected count. grab_count is how many were matched.
- If grab_count >= missing_count (all resolved): outcome = "grabbed"
  - detail = f"grabbed: {grab_count}/{missing_count} episodes"
  - stat_increments: if queue_type == "missing" -> {"episodes_found": grab_count}, if "cutoff" -> {"episodes_updated": grab_count}
- Else if grab_count > 0 but < missing_count:
  - If entry's CURRENT outcome is "searched": outcome = "partial"
    - detail = f"partial: {grab_count}/{missing_count} episodes"
    - NO stat increments yet (per user decision: increment on terminal state only)
  - If entry's CURRENT outcome is "partial": leave as "partial" (still waiting, might upgrade to grabbed)
    - Skip update (no-op)
  - In both cases: if window expired, this IS the terminal state:
    - outcome = "partial" (stay partial)
    - detail = f"partial: {grab_count}/{missing_count} episodes (window expired)"
    - stat_increments: if queue_type == "missing" -> {"episodes_found": grab_count}, if "cutoff" -> {"episodes_updated": grab_count}
- Else if grab_count == 0 and window expired: outcome = "unresolved"
  - detail = "no grabs detected within tracking window"
  - stat_increments = None
- Else: skip (still within window, leave current outcome)

e. If outcome determined, call `update_outcome_and_stats(db, history_id, outcome, detail, app=app, queue_type=queue_type, stat_increments=stat_increments)`.
f. Increment the appropriate counter in the return dict.

5. Log summary: "Tracking: {grabbed} grabbed, {partial} partial, {unresolved} unresolved, {errors} errors"

**Important implementation details:**
- Import from fetcharr.correlation: SearchRecord, CorrelationResult, correlate_grabs
- Import from fetcharr.db: get_trackable_entries, update_outcome_and_stats
- Use `from datetime import UTC, datetime` for current time
- Use `datetime.fromisoformat(entry["timestamp"].replace("Z", "+00:00"))` to parse searched_at (same pattern as correlation.py's _parse_iso)
- Use loguru logger for all logging
- Catch httpx.HTTPError and pydantic.ValidationError around get_grab_history calls (per CLAUDE.md error patterns)
- Use `from __future__ import annotations` at top
- Do NOT import types from typing that are available as builtins (per ruff UP rules)
- The function must handle entries with missing_count=None gracefully for Sonarr (treat as 0 expected, so any grab = "grabbed")
