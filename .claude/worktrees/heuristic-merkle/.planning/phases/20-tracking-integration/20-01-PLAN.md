Add two new async functions to fetcharr/db.py after the existing CRUD section:

**1. `get_trackable_entries(db: aiosqlite.Connection) -> list[dict]`**

Query search_history for rows where:
- outcome IN ('searched', 'partial') — these are the entries still awaiting resolution
- item_id IS NOT NULL — entries without item_id cannot be correlated

Return list of dicts with keys: `id`, `app`, `queue_type`, `item_id`, `season_number`, `missing_count`, `timestamp` (the searched_at time).

Use `db.row_factory = aiosqlite.Row` pattern (set then reset) matching the existing `get_recent_searches` pattern. Order by `id ASC` (oldest first, so we resolve the oldest entries first).

**2. `update_outcome_and_stats(db: aiosqlite.Connection, history_id: int, outcome: str, detail: str, *, app: str, queue_type: str, stat_increments: dict[str, int] | None = None) -> None`**

In a single transaction (no intermediate commits):
1. UPDATE search_history SET outcome = ?, detail = ? WHERE id = ?
2. If stat_increments is provided and non-empty, UPDATE lifetime_stats for the given app, incrementing the specified columns. The stat_increments dict maps column names to increment values, e.g. `{"movies_found": 1}` or `{"episodes_found": 3, "episodes_updated": 2}`.
   - Build the SET clause dynamically: `SET col1 = col1 + ?, col2 = col2 + ? WHERE app = ?`
   - Only allow known column names: movies_found, movies_updated, episodes_found, episodes_updated (raise ValueError for unknown columns)
3. COMMIT once at the end.

Per user decision: atomic -- update outcome + increment stats in the same DB transaction.

Both functions use loguru for debug-level logging. Follow existing code conventions: no bare except, standard error patterns.
